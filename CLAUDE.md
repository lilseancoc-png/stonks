# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`stonks` is a single-page **Option Contract Rater**. It is a mostly-static site (HTML + CSS + IIFE JS) served from the repo root, with Vercel serverless functions in `api/` for things the browser cannot do itself (live Yahoo quotes/chains, the live Fed Funds rate; the **gated private-data reader** `api/data/*`; the **Discord OAuth** gate `api/auth/[action]`; plus a now-**dormant** Supabase-backed portfolio stack — AI portfolio review + positions — that was unwired from the site in #269 and is excluded from the deploy via `.vercelignore`). There is **no bundler** and **no framework** — `index.html`, `app.js`, `styles.css` are committed to the repo and shipped as-is.

> **The site is a FREEMIUM product (Path B private-data migration).** All `data/*.json` are **NOT in the repo** — `data/` is gitignored and lives in a **private Vercel Blob store**, served through `/api/data/*`. That reader is **tiered** (`lib/premium-keys.mjs`): FREE keys (per-ticker chains, calendar, heatmap, 13F, macro, fear-greed, correlations, the grade index, streaks, …) stream to **anyone** and edge-cache; PREMIUM keys (picks/briefs/narratives/earnings-calls + transcript-<SYM> details/unusual/volume/OI/track-record + the premium half of the manifest) stream only to a holder of a valid **Discord server-role** session. The app shell + live `/api/*` proxies are **open**; only the premium TABS (Market Analysis, Stock Picks, Briefs, Narratives, Earnings Calls, Unusual Flow, Volume, Gamma Exposure, Index Calendar) are gated — a non-member sees an upsell lock card — and two tabs are **role-hidden** on top of premium (Top Picks via the `tp` claim, Track Record via `tr`). The whole gate is behind a `PRIVATE_DATA_ENABLED` flag (Vercel env **and** GitHub Actions repo variable). **Full architecture + the cutover history is in [`docs/private-data-migration.md`](docs/private-data-migration.md); read it before touching `data/` flow, the workflows, `middleware.js`, `lib/datastore.mjs`, `lib/session.mjs`, `lib/premium-keys.mjs`, or `api/{data,auth}`.** See the "Private data + Discord-role gating" section below.

Three GitHub Actions workflows (`daily.yml`, `unusual-flow.yml`, `oi-tracker.yml`) re-generate the data on a schedule by invoking Node scripts. With the flag ON they **hydrate `data/` from the store (`sync-data.mjs pull`) → build/scan → flush back (`sync-data.mjs push`)** and commit only the render output (`index.html`/`app.js`/`styles.css`) to the public repo; the resulting commit to `main` triggers a Vercel deploy. (Flag OFF = the legacy model: `data/` committed to the repo.)

## Private data + Discord-role gating (Path B)

The site monetizes via a **freemium split**: most tabs are free to browse; a premium subset is gated behind **Discord server-role membership**, with all data moved **out of the public repo** into a **private Vercel Blob store**. Full spec + cutover history: [`docs/private-data-migration.md`](docs/private-data-migration.md). **The free/premium split is single-sourced in [`lib/premium-keys.mjs`](lib/premium-keys.mjs)** (`isPremiumKey(key)`) — shared by the Edge middleware and the Node `api/data` reader, and mirrored client-side by `PREMIUM_TABS` in `scripts/render/app-js.mjs`. Premium = Market Analysis (the market tape / risk barometer / regime history + the grade-any-ticker search and held-position checker), Stock Picks (the shares-only quality-dip screen, `data/stock-picks.json`), Briefs, Narratives, Earnings Calls (the transcript AI briefs: `data/earnings-calls.json` + the flat `data/transcript-<SYM>.json` per-ticker details, gated via the `PREMIUM_PREFIXES` prefix match in `premium-keys.mjs` — flat because Vercel's non-Next router can't route nested paths into `api/data/[...path].js`), Unusual Flow, Volume, Gamma Exposure, Index Calendar (and the data files backing them); **Top Picks and Track Record are a stricter, role-HIDDEN tier on top of premium** (per-key claims `tp`/`tr` in `roleClaimForKey`); everything else is free. The moving parts:

- **`lib/datastore.mjs`** — backend-agnostic private-store adapter. `get`/`put`/`del`/`list` over `data/`-relative keys (keys map 1:1 to object pathnames). **`createStore()` selects the backend by env: Cloudflare R2 (default, S3-compatible via `aws4fetch` SigV4) when `R2_ACCOUNT_ID/R2_ACCESS_KEY_ID/R2_SECRET_ACCESS_KEY/R2_BUCKET` are set, else Vercel Blob (`BLOB_READ_WRITE_TOKEN`, `access: "private"`) as the fallback** — so the cutover is a pure env-var flip and rollback is unsetting the four R2 vars. Content is fetched credential-authenticated — **never** a public URL. R2 is the default because Blob's free tier caps "advanced" ops (every `put`/`list`) at 2,000/mo, which the per-bake full re-sync exhausts in ~a day; R2's free tier (1M class-A ops/mo) absorbs it.
- **`scripts/sync-data.mjs`** — the hydrate/flush boundary: `pull` (store→local `data/`), `push --owner=bake|unusual|oi` (local→store), `seed` (one-time full upload). The build/scan internals are unchanged — they still operate on a local `data/` dir. **Ownership model** (re-encodes the old git `SCANNER_FILES` split so serialized runs don't clobber): the bake pushes everything except the scanner-exclusive keys and delete-stales only the per-ticker + `iv-history/` prefixes; scanners push upsert-only; `heatmap`/`ai-usage`/`briefs`/`manifest.json` are co-owned (all push them, regenerated deterministically); `picks-watchlist.json` is **request-time-owned** (`api/watchlist.js`, written on user clicks) — `REQUEST_TIME_EXCLUSIVE`, no workflow may push or delete it.
- **`lib/session.mjs`** — runtime-agnostic signed-cookie sign/verify (`jose` HS256) + cookie helpers, shared by the Node api handler **and** the Edge middleware (so it must stay Edge-safe: `jose` + `TextEncoder`, no `node:crypto`).
- **`api/auth/[action].js`** — ONE dynamic-route function (URLs unchanged) for `discord-login` / `discord-callback` / `logout` / `me`. OAuth `identify guilds.members.read` → CSRF `state` cookie → server-side token exchange → guild-member/role check → 12h HttpOnly/Secure/SameSite=Lax session cookie minted only when the user holds **any** accepted role (`DISCORD_REQUIRED_ROLE_ID` ∪ `DISCORD_REQUIRED_ROLE_IDS`; failures → `/welcome.html?denied=<reason>`). The multi-role union exists because a Discord-managed subscription role can't be hand-assigned (not even by the owner), so you accept it **plus** a normal owner/comp role you control. Consolidated into one function to stay under Vercel **Hobby's 12-serverless-function limit** (the 4 dormant portfolio fns are `.vercelignore`d for the same reason).
- **`lib/premium-keys.mjs`** — the single source of truth for the free/premium split: `isPremiumKey(key)` over `data/`-relative keys. Dependency-free + Edge-safe (imported by both the middleware and `api/data`). Anything not in its `PREMIUM_KEYS` set is free. A second map, `ROLE_RESTRICTED_KEYS` (`roleClaimForKey(key)` → `tr`/`tp`), names the per-key session claim for the two role-hidden tiers: `tr` for the Track Record files (`picks-accuracy/-changes/-roster.json`, `grades-history.json`), `tp` for the Top Picks files (`picks.json`, `picks-open.json`); `market-analysis.json` (the Market Analysis tab's regime payload) is premium but NOT role-restricted. **Note `grades.json` (the all-tickers grade index) is FREE** — the "grade any ticker" tool is a free feature — while `grades-history.json`/`grades-daily.json` are premium.
- **`api/data/[...path].js`** — the **tiered** reader: free keys stream to anyone with a short `public` edge cache; premium keys require a valid session (else 401) and are `private, no-store`. **Gotcha:** Vercel does NOT populate the catch-all `req.query.path` when the route is reached via a middleware `rewrite()`, so the key is derived from the **request URL path** (URL-normalized) with `req.query.path` as the fast path. Hard-404s unless `PRIVATE_DATA_ENABLED==="1"`.
- **`middleware.js`** (Edge) — now just the `/data/*` router. Flag OFF → `next()` (today's behavior). Flag ON → rewrites `/data/*` to `/api/data/*` (which self-tiers). The app shell + live `/api/*` are **open** (no session check in the Edge layer anymore); premium enforcement lives entirely in `api/data`. Zero imports beyond `@vercel/edge` (matcher narrowed to `/data/:path*`).
- **`welcome.html`** — the hand-maintained, self-contained Discord-login + denied-reason lander (the **only** remaining standalone HTML page — the reference/legal/info pages are now in-app tabs, see the docs.mjs note below). No longer a forced gate (the site is browsable at `/`); it's reached via the "Log in"/"Unlock" CTAs and the OAuth denied redirects, and links back to the free site.
- **Client gate** (`scripts/render/app-js.mjs`): `PREMIUM_TABS` + `IS_MEMBER`/`GATE_ON` (from `/api/auth/me`, which now returns an `enabled` flag) drive the UI half — a non-member opening a premium tab gets a `.premium-lock` upsell card (loaders skipped) and premium nav items show a 🔒 (`body.is-member` toggles it); the header chip shows a "Log in" button when signed out. Boot fetches `/api/auth/me` + both manifest sidecars before first paint so the initial `selectTab` sees the right membership. Fail-open: a missing/failed `/me` ⇒ treated as ungated (no false lockout).
- **Manifest split** (`scripts/render/html.mjs` + `app-js.mjs`): the inlined `STONKS_MANIFEST` is only the non-sensitive **shell** (+ `deferred` flag). The rest splits by tier into **two** sidecars: `data/manifest.json` (PREMIUM, gated — narratives, sector overviews, recently-ended, unusual snapshot) and `data/manifest-free.json` (FREE, public — macro headlines, spots, fear-greed, macro, market backdrop). `app.js` fetches **both** + merges before first paint; the premium one 401s for non-members (degrades to no-premium). Keeping `manifest.json` = the premium key means the pre-cutover combined file stays gated (no leak window).
- **`vercel.json`**: no longer forces a blanket `/data/*` cache header — `api/data` is the authority per tier (free → `public, s-maxage`; premium → `private, no-store`). Premium content still must never be shared-cached.
- **The two flags** must align: `PRIVATE_DATA_ENABLED=1` in **Vercel env** (gate) **and** as a **GitHub Actions repo variable** (workflows). The store-write token `BLOB_READ_WRITE_TOKEN` must be in **both** Vercel project env (for `api/data`) **and** GitHub Actions secrets (for the workflows). Discord/session env (`DISCORD_CLIENT_ID/SECRET`, `DISCORD_GUILD_ID`, `DISCORD_REQUIRED_ROLE_ID`, the optional `DISCORD_TRACKRECORD_ROLE_ID` / `DISCORD_TOPPICKS_ROLE_ID` for the stricter Track Record / Top Picks tiers, `SESSION_SECRET`) are Vercel-only (the auth fns).

## Commands

```bash
# Full rebuild — hits Yahoo for chains + history, optionally calls Gemini, and
# rewrites index.html, app.js, styles.css, and every data/*.json. Requires
# Node >=20. GEMINI_API_KEY is optional (AI narratives + news takes are
# skipped without it). This is the same command the daily-build workflow runs.
node scripts/build.mjs
# or: npm run build

# Regenerate ONLY index.html / app.js / styles.css from existing data/*.json
# (no Yahoo, no Gemini). Use this when you only touched the render layer
# in scripts/render/ (or one of the shared helpers they import from build.mjs).
# Also seeds data/heatmap.json from per-ticker JSON IF (and only if) that file
# is missing; an existing hourly-refreshed heatmap.json is left untouched.
node scripts/regen-static.mjs

# Regenerate ONLY data/calendar.json (macro releases, FOMC, FedWatch, earnings
# AM/PM sessions) without redoing the per-ticker chain fetches. Also rewrites
# data/fedwatch-history.json (the day's FedWatch snapshots + lastKnownFedRate).
node scripts/regen-calendar.mjs

# Hourly unusual-options-flow scan. Writes data/unusual.json (today's flagged
# contracts), data/unusual-history.json (rolling hourly snapshots),
# data/unusual-log.json (7-day flag log), plus the intraday volume + S/R-break
# pass (data/volume-flags.json, data/volume-history.json) and AI flow takes
# (data/flow-explanations.json). Run via the unusual-flow workflow.
node scripts/scan-unusual.mjs

# Hourly heatmap refresh — one batched Yahoo quote call rewrites the live `ch`/`sp`
# fields in data/heatmap.json (sector/industry/name come from the nightly bake;
# market-cap is refreshed hourly from the live quote when present). Intra-session
# runs add no AI cost (pure Yahoo). After the 16:00 ET close the run also makes
# ONE Gemini call (AI_EOD_MODEL, default gemini-2.5-flash-lite) to write the
# per-sector EOD recap (the `eodSummary` block) into heatmap.json, recorded
# against the shared data/ai-usage.json budget; generated at most once per ET
# day and carried forward by later runs. Skipped without GEMINI_API_KEY.
# Runs as a second step inside the unusual-flow workflow.
node scripts/refresh-heatmap.mjs

# Twice-daily near-term open-interest tracker (pre-market + EOD). Snapshots the
# front two expirations per ticker — top-OI strikes, call/put walls, ΔOI vs the
# prior trading day, gamma-squeeze score. Writes data/oi-tracker.json (current
# snapshot) + data/oi-history.json (rolling). Run via the oi-tracker workflow.
node scripts/scan-oi.mjs

# Regenerate ONLY data/picks.json (+ data/picks-accuracy.json + data/grades.json
# + data/grades-history.json, the grade-change log + data/picks-changes.json, the
# picks in/out churn log + data/picks-roster.json, the Top-10 in/out roster
# snapshot + data/stock-picks.json, the shares-only Stock Picks quality-dip
# screen) from existing per-ticker data/*.json + streaks/trends/
# unusual. Use when only the picks/grading algorithm changed — no Yahoo, no Gemini.
# (Unlike the bake, regen-picks doesn't wipe data/, so it reads the live
# accumulating files directly. It preserves each pick's firstSeen day-streak and
# writes the deterministic picks-changes events, but skips the AI one-liner.)
node scripts/regen-picks.mjs

# Standalone earnings-call transcript pass — discover new transcripts (Motley
# Fool primary, MarketBeat fallback) + mint the AI briefs into data/earnings-calls.json
# and data/transcript-<SYM>.json without the full bake (no Yahoo). Same knobs
# as the bake: TRANSCRIPTS_PER_BUILD (AI summaries per run, default 6),
# TRANSCRIPT_PROBES_PER_BUILD (quote-page backfill probes, default 20),
# AI_TRANSCRIPT_MODEL (default gemini-3.5-flash) / AI_TRANSCRIPT_THINK /
# AI_TRANSCRIPT_CHARS. Needs a hydrated data/ + GEMINI_API_KEY (keyless =
# carry-forward only).
node scripts/regen-transcripts.mjs

# One-shot maintenance: backfill the `autoPick` field (the best call + best put the
# Top Picks engine would select for each name, scored with the exact same
# pickContractForPick the picks pipeline uses) into every committed data/<SYM>.json
# WITHOUT a network build. Powers the Grade tab's "★ Top-Picks grade" banner. The
# full build writes this in writeChainFiles(); this reproduces it offline because
# regen-static.mjs never touches data/.
node scripts/backfill-autopick.mjs

# Read-only diagnostics (no network, no writes — not part of any workflow).
# Loss attribution for the resolved Top Picks track record: decomposes realized
# losses into DIRECTION (signal was wrong) vs THETA/VOL (stock was flat/favorable
# but long premium bled) by repricing each pick with Black-Scholes at exit, IV
# held constant. Decides the picks-engine roadmap (verticals vs score fixes).
node scripts/diagnose-pick-losses.mjs
# Universe-wide grade IC: joins the daily whole-universe grade snapshots
# (data/grades-daily.json, upserted once per ET day by the bake + regen-picks)
# with the committed priceSeries closes and reports the grade's cross-sectional
# Spearman IC + top-vs-bottom-decile spread at 5/10/14-trading-day horizons —
# the fast "can the score call 2-week direction?" read (~138 names/day instead
# of the ~5-per-build enrolled roster). Degrades to "insufficient sample" until
# grades-daily.json accumulates a few sessions.
node scripts/diagnose-grade-ic.mjs
# A/B parity check for the AI_SIGNALS_COMBINED cost optimization (folding the
# per-ticker Major-Contract + Guidance extraction into the combined ticker call).
# Diffs the fundamentals-pillar rows of two data/grades.json snapshots produced
# with AI_SIGNALS_COMBINED=0 vs =1 (see the file header for how to capture them).
node scripts/ab-signals-merge.mjs /tmp/grades-off.json /tmp/grades-on.json

# Reset the Top Picks track record in the PRIVATE store after a strategy change
# (so the win-rate / closed-P&L don't blend old + new strategy). MUTATES the
# store — requires the same R2_*/BLOB creds as sync-data.mjs. DRY-RUN by default;
# --apply to execute. Always resets picks-accuracy.json (the track record) and
# DELETES the orphaned day-trades.json/-history.json (the Day Trades feature was
# removed); --picks-logs adds the picks in/out churn + roster, --grade-logs adds
# the grade-change log + IC substrate, --all adds both. --empty (default)
# overwrites each key with a valid empty payload (UI shows "no history yet");
# --delete removes the key (next bake recreates it). Every key was verified safe
# — all readers self-heal on a miss.
node --env-file=r2.env scripts/wipe-history.mjs --all          # dry run
node --env-file=r2.env scripts/wipe-history.mjs --all --apply  # execute

# Local serving
python3 -m http.server 8000   # static only — /api/* endpoints will 404
npx vercel dev                # full stack including api/quote, api/chain, etc.
```

There is **no test suite, no linter, and no type checker** wired into `package.json`. The only npm script is `build`. Verify changes by re-running the relevant generator and diffing the committed artifacts, or by loading the page locally.

The `createBlobStore` adapter is kept as a documented fallback (auto-selected only if the R2 vars are unset), but the token is **no longer wired into the workflows** — re-enabling Blob means re-creating a store, re-adding this token to Vercel + Actions, and re-seeding it. |

Every `GoogleGenAI` client also carries a per-request `AI_HTTP_TIMEOUT_MS` (default 120000) so a hung request aborts into the retry ladder instead of holding a concurrency slot for minutes. `AI_CHART_CONCURRENCY` (code default 6, `daily.yml` sets 12) widens the chart-pattern pass on its twice-daily cache-rollover builds. |

## High-level architecture

### Two halves: bake-time vs. request-time

The site is built around a strict split:

1. **Bake time** (`scripts/build.mjs`, run by `.github/workflows/daily.yml` 8×/trading day — 9:30 ET open, then hourly 10:00–16:00 ET): fetches every curated ticker's option chain + ~1yr of daily bars from Yahoo, computes technicals (RSI/MACD/SMA/S&R/IV regime), asks Gemini for per-ticker news takes and the global narratives view, then writes every artifact the page needs into the repo:
   - `index.html` — page shell with a `~120 KB` `window.STONKS_MANIFEST` JSON blob inlined (ticker list, sectors, narratives, sector overviews, spots, unusual flow snapshot, build timestamp — NOT the OI tracker or volume-flags payloads, which the browser lazy-fetches from `data/oi-tracker.json` / `data/volume-flags.json` on tab entry; only their `oiMeta`/`volumeFlagsMeta` stubs ride inline).
   - `app.js` — generated single IIFE that runs the Tickers / Narratives / Calendar / Grade / etc. tabs. **Never edit `app.js` directly.** Its source is the template string returned by `renderAppJs()` in [`scripts/render/app-js.mjs`](scripts/render/app-js.mjs). Same applies to `styles.css` ([`scripts/render/styles-css.mjs`](scripts/render/styles-css.mjs)) and the page shell in [`scripts/render/html.mjs`](scripts/render/html.mjs).
   - `data/<SYMBOL>.json` — per-ticker option chain + technicals + AI news take. Loaded lazily by the browser when a ticker is picked. Also carries `earningsHx` (the last ~8 earnings prints + the upcoming one — Grade tab's Earnings-history card), sliced per ticker by `attachEarningsHx` from `data/earnings-history.json`: an accumulating store (announcement dates + AM/PM + EPS backfilled from Yahoo's earnings-dates endpoint; price reactions from daily bars; straddle-implied move + ATM IV stamped live inside the final week before each print, with older prints getting an IV-crush-derived expected-move estimate — `impliedMoveFromIvCrush` → `impliedMoveEstPct`, rendered `~±`) that follows the same read-before-wipe rule as the other histories (`readEarningsEventsHistory` before `writeChainFiles`, written back after).
   - `data/{calendar,picks,picks-accuracy,picks-changes,picks-roster,grades,grades-history,grades-daily,trends,trends-history,streaks,13f,ai-usage}.json`, the macro/rate series (`macro,macro-history,rfr-history,fedwatch-history,iv-history/*`), and the bake-written `heatmap.json` + CNN Fear & Greed (`fear-greed,fear-greed-history`) — every other tab's data. (`grades.json` is the all-tickers 4-pillar grade index — every tracked symbol's score/conviction/pillars, not just the actionable top picks — powering the Top Picks tab's "grade any ticker" search. `grades-history.json` is the whole-universe grade-change log; like `picks-accuracy.json` it accumulates across builds, so `main()` pre-reads it BEFORE `writeChainFiles` wipes `data/` — same trap. `grades-daily.json` is the once-per-ET-day whole-universe grade-total snapshot — the substrate for `scripts/diagnose-grade-ic.mjs` — and accumulates the same way, pre-read before the wipe.)
   - `data/heatmap.json` carries one extra AI-written block: after 16:00 ET, `refresh-heatmap.mjs` writes an `eodSummary` (headline + per-sector EOD recap from one `AI_EOD_MODEL` call) into it, generated at most once per ET trading day and carried forward by later hourly runs until the ET date rolls.
   - `data/briefs.json` — the **Brief** tab's rolling market digest (`{ current }` — one brief, `{ kind, headline, summary, highlights[], ...deterministic chips }`), **re-minted HOURLY by the bake** (`buildMarketBriefs` in `build.mjs`, called only from the bake's `main()`; the old pre-market/post-close `regen-brief.mjs` mints are gone). Gated to at most once per ET **hour** (a same-hour re-run carries the existing brief forward, so re-running stays safe) — the hourly bake cadence means every build ships a fresh read. The framing follows the clock (`briefKindForHour`): a build before 10:00 ET writes the **morning** setup (yesterday's index close + overnight correlations + macro + Fear & Greed + SPY/QQQ 20D levels + prior-session flow + the day's calendar + top picks), builds through the session write an **intraday** where-the-tape-stands read, and 16:00 ET onward the **afternoon** closing read (both from the session's breadth/movers/sectors + 52-week extremes + volume standouts + unusual flow + macro + picks + what's-next). Each mint is one `AI_BRIEF_MODEL` (default `gemini-2.5-flash-lite`) call — same read-before-wipe (`readPriorBriefs` before `writeChainFiles`) / write-after-wipe pattern as the `eodSummary`. Self-skips without `GEMINI_API_KEY`; the deterministic stat/chip blocks (`gatherBriefSignals`) are computed in-code, the AI only writes the prose. Among those blocks is a **tickers-to-watch** section (`buildBriefWatchlist`, exported): a deterministic single-name event/news screen over the whole universe — per-ticker AI news takes (bullish/bearish only; the keyless fallback take is "uncertain" and never fires), dated catalysts, capital-raise/buyback headlines, earnings timing, unusual flow, heavy relative volume, big 1-day moves, 52-week extremes — deliberately NOT sourced from the Top Picks roster (overlap is badged `pick: true`); a name needs ≥1 event-ish reason or a 2-signal tape pile-up, ships ≤`BRIEF_WATCH_MAX` (6) names (broad index ETFs excluded), and the list also rides the AI prompt so the prose can cite it. NOT in the manifest — the browser lazy-loads it on tab open (`loadBrief`/`renderBrief` in `app-js.mjs`, which still renders a legacy `{ morning, afternoon }` payload across the cutover).
   - `data/correlations.json` — overnight cross-market signals for the **Overnight markets** tab (under Macro) + the Grade tab's per-ticker "overnight peer read". The bake sweeps a curated `GLOBAL_MARKETS` set (foreign indices/equities + FX + US futures + **commodities** (crude/copper/gold/silver/nat-gas) + **rates** (10Y/30Y) + **crypto** (BTC)) from Yahoo, snapshots each one's last completed session move, and computes a trailing return correlation + OLS β of each US name vs its mapped peers (`GLOBAL_PEER_GROUPS`/`GLOBAL_PEER_OF_TICKER` — tech groups *and* non-tech `energy`/`metals`/`industrials`/`power`/`logistics`/`rates`/`crypto`; the β **sign** carries direction, so one group serves both same- and inverse-direction names, e.g. oil vs fuel-burning logistics). Rebuilt every bake (no cross-build accumulation) but follows read-before-wipe: `readPriorCorrelations()` lets a thin foreign sweep fall back to last-good rather than blanking the tab. Bake-time only — the 9:30 ET build is the first to capture the just-closed Asian session; the browser lazy-loads the file (it is NOT in the manifest). `chart()` in the build fetches these foreign symbols directly, so they bypass `lib/yahoo.mjs::SYMBOL_RE` (the `/api` proxies can't reach them).
   - `data/ai-capex.json` — the **AI CapEx** tab (under Macro). Aggregate "Magnificent 7" capital expenditure pulled from SEC XBRL via the companyconcept REST API (`PaymentsToAcquirePropertyPlantAndEquipment`, AMZN's `PaymentsToAcquireProductiveAssets`); `reduceCapexFacts` derives each name's full-fiscal-year totals + a trailing-12-month run-rate (cash-flow roll-forward), summed for the this-FY-vs-last-FY aggregate. The same probe also fetches each name's **total revenue** (`AI_CAPEX_REVENUE_CONCEPTS`: `Revenues` / the ASC 606 contract-revenue tags) through the same reducer, so the payload carries a per-company `rev` block + a `totals.revenue` aggregate (combined revenue, revenue-YoY vs capex-YoY over the same subset, capex-as-%-of-revenue latest-FY/prior/TTM) — the tab's "revenue check" strip. Spot sources only publish the current session, so `buildRamPricesPayload` accumulates a per-item daily history across builds (`spot.history`, upserted by ET date) to compute 7d/30d % changes — which is why this file follows read-before-wipe (`readPriorRamPrices`). The retail side ships a median-of-categories composite index + 7d/30d/3mo/1y changes. Both sides carry last-good forward (stale-marked) on a fetch/parse miss. FREE key. Browser lazy-loads it (`loadRamPrices`/`renderRamPrices`).

### Cross-build AI caches (token conservation)

The bake runs 8×/trading day (9:30 ET open, then hourly to the 16:00 close), but several Gemini outputs change far more slowly. Four caches cut repeat token spend:
- `data/ticker-judgment-cache.json` — the **combined news+fundamentals judgment** cache (`attachTickerJudgments`, the single most expensive AI pass: one call per ticker per bake carrying up to 10 headlines *with article bodies*). Keyed per ticker on the ET date + a hash of the **raw** headline set + the slow-moving fundamentals facts (last reported quarter, next earnings date, analyst consensus) + the models + the `AI_SIGNALS_COMBINED` shape — deliberately NOT on the price-derived prompt fields (spot/market-cap/P/E drift every build); instead a reused entry re-reads once spot drifts >2% (`AI_TICKER_CACHE_DRIFT`) from the price the take was generated at (the entry keeps its original spot on reuse, so drift accumulates). The headline half of the key is **churn-tolerant**: Yahoo's top-10 list turns over intraday (one new SEO piece busted the exact-match key and held reuse to ~20%), so a build whose ONLY delta vs the cached read is ≤`AI_TICKER_CACHE_NEWS_TOLERANCE` (default 1) genuinely-new headline *titles* reuses anyway — price-moving news still re-reads via the spot-drift guard, and new-title counts accumulate against the original entry's title set, so a drip of articles re-reads once it crosses the tolerance (`0` restores exact-match-only). A hit also skips the article body-fetch wave, saving wall-clock. Per-article body input is capped at `ARTICLE_MAX_BODY_CHARS` (3000; env `AI_ARTICLE_BODY_CHARS`) — the direct input-token lever for this (most expensive) pass. The same entry also carries the **split contract/guidance extraction** (`attachAiContractGuidance` stores its result as `signals`, `null` = ran-and-found-nothing), so with `AI_SIGNALS_COMBINED` off that second per-ticker call is skipped on unchanged headlines too. Same read-before-wipe / write-after-wipe rule; keyless builds carry the prior map forward; the zero-headline fallback take and failed calls are never cached (retried next build). `AI_TICKER_CACHE=0` disables; bump `TICKER_JUDGMENT_CACHE_VERSION` after a prompt/schema change.
- `data/chart-pattern-cache.json` — the detector reads ~1 month of **30-minute intraday** bars, so it's keyed per ticker on the ET date + **AM/PM half-day bucket** (`chartPatternBucketKey`): the first build in each half re-reads, the rest of that half reuse (≈2 reads/ticker/trading day). Deliberate trade-off: a fast-forming intraday pattern can lag by a few hours within a session. Entries also carry a **bar-series signature** (`chartPatternBarsSig`, the exact window the model would be shown) — when the bars are unchanged since the cached read (market closed: weekend/evening/holiday runs), the read is reused even across bucket rollovers, so frozen charts are never re-rated (this pass runs on full Flash with thinking enabled — per-read it's the priciest call in the build). Follows the same **read-before-wipe / write-after-wipe** rule as the histories below (`readChartPatternCache()` before `writeChainFiles`, `writeChartPatternCache()` after). A keyless build returns the prior cache unchanged rather than clobbering it. Only successfully-detected names are cached, so a failure retries next build. The detector is **multimodal**: `lib/chart-image.mjs` (a dependency-free, pure-JS-zlib PNG renderer — close-price line + high/low wick band + 50/200D SMA overlays + a volume strip, no rasterized text) renders the bars to an actual chart *image* that Gemini SEES, instead of handing it a text table of numbers. That image is why this one call must stay on `AI_CHART_MODEL=gemini-2.5-flash` (Flash-Lite reads the image poorly — see the env-var table).
- The unusual-flow scanner's `data/flow-explanations.json` is the analogous per-contract cache (see `scan-unusual.mjs`) — a contract flagged once is explained once and reused free for the rest of the session.
- `data/pick-thesis-cache.json` — the Top Picks **everything-aware thesis** cache (`generateAiTheses`, model `AI_THESIS_MODEL`, default **full `gemini-3.5-flash` with a real thinking budget** (`AI_THESIS_THINK`, default 1024) — the final grader judges ≤10 names/build, so quality > tokens; `AI_THESIS=0` disables). **Web-search-grounded (2026-07-10)**: each cache-miss name is a TWO-step call — one Google-Search-grounded research pass (`fetchThesisWebResearch`, model `AI_THESIS_SEARCH_MODEL`; fresh news/catalysts/analyst moves + anything contradicting the direction, as dated bullets) whose digest + source list ride the second, forced-JSON grader call (the API rejects `googleSearch`+`responseSchema` in one call; a failed research pass degrades to the ungrounded grade; `AI_THESIS_SEARCH=0` disables; sources ship on `thesisCard.ai.webResearch` for audit). Applied per **data-gated** name (the deterministic conviction bar + re-entry/avoid-timing screens), **capped at the top `PICKS_MAX_AI_THESES` (= `PICKS_COUNT`, 10) survivors by deterministic conviction** (the rest ship deterministic-only; no bench below the cut), where the AI is the **final grader** (its `grade` sets classification + a `reject` veto — the roster order stays deterministic, and its `entryVerdict` is the final buy-now/wait call on the entry gate — including the momentum-ride-vs-chase judgment on soft-extended names; the prompt carries the full evidence table — every pillar signal FOR/AGAINST, technical structure, the OI walls/gamma score, `earningsHx` incl. the pre-earnings drift, trajectory, capital events, the forward macro calendar, IV momentum, the deterministic entry read), keyed per `symbol:side` on a signature that turns over with the rounded grade, the in-direction driver keys, the macro state + the relevant axes' directions, a hash of the AI **news take**, the fundamental verdict, the IV bucket, the deterministic entry state, the nearest scheduled macro event (a print clearing / a new event entering the horizon re-grades), **and the ET date** (a web-grounded verdict never outlives the trading day its research ran on) — so it re-reads on a material macro/news/entry shift or a date roll, not every build. Same read-before-wipe (`readPickThesisCache()` before `writeChainFiles`) / write-after (`writePickThesisCache()` after the picks file) rule; carries the prior thesis forward on a keyless build; **not** written by `regen-picks` (offline → deterministic market read only). The deterministic thesis + macro read ship regardless (graceful keyless degradation).

`AI_RPM` (default 100, the per-minute AI pacer in `build.mjs`) is set to `600` in `daily.yml` for the funded Tier-1 project — Flash/Flash-Lite carry 1K-4K RPM quotas, so 300 keeps a wide cushion while shrinking the RPM-paced floor of the per-ticker AI passes. **Leave it unset on a free-tier fork** (Gemma free = 15 RPM; even the default 100 is too high there).

### Charts are interactive via one delegated hover engine

Every inline-SVG series chart gets a hover/tap readout from ONE shared engine in `app-js.mjs` (`chHoverAttr` + the `initChartHover` IIFE, in the top-of-file utilities): a chart opts in by emitting a `data-ch='[[x,y,"label"],…]'` attribute (viewBox coords + preformatted label, built with `chHoverAttr(points)`; `\n` in a label = a tooltip line break), and a single delegated `pointermove`/`pointerdown` document listener drives a shared fixed-position crosshair + snap-dot + tooltip (`.ch-line`/`.ch-dot`/`.ch-tip` in `styles-css.mjs`). Coordinate mapping goes through `getScreenCTM()`, so it's exact for any `viewBox`/`preserveAspectRatio` combination (several charts stretch with `preserveAspectRatio="none"`, where in-SVG overlay text would distort) — and because the listener is delegated, charts rebuilt via `innerHTML` stay interactive with zero re-wiring. When adding a NEW SVG chart, emit `data-ch` instead of writing a bespoke handler. The charts with richer bespoke overlays (Grade price chart, IV term structure, fundamentals/earnings history, F&G history spark, heatmap treemap, regime calendar) keep their own handlers — don't double-wire them with `data-ch`. DOM-bar charts (not SVG — OI ladder, AI-CapEx bars, breadth/social/flow split bars, streaks sparks) use plain `title`/`data-tip` attributes instead.

- `js/streaks.js` (ES module) — the Streaks tab. Renders `data/streaks.json`.

**Dormant portfolio stack — don't "fix" the missing script tag.** The Portfolio tab, landing card, pane, and its script/style loads were removed from the page templates in commit #269 ("Remove portfolio from site"). `js/portfolio.js`, `js/auth.js`, `portfolio.css`, `lib/greeks.mjs`'s client import, and the `api/{portfolio-review,close-position,delete-trade,contract,config}` endpoints + `supabase/schema.sql` are all still tracked but **nothing in the current page loads them**. The intentional design is to preserve the backend so the tab can be re-enabled later — treat these files as dormant unless you deliberately re-add a `<script type="module" src="js/portfolio.js">` tag in `scripts/render/html.mjs`. (For reference: `js/portfolio.js` used `js/auth.js` for Supabase auth — config from build-time inlined `window.STONKS_SUPABASE`, falling back to `/api/config` at runtime — and `lib/greeks.mjs` for client-side Black-Scholes.)

### Math is duplicated on purpose

Black-Scholes greeks live in **three** places: (1) the inlined `greeks`/`ncdf`/`npdf` near the top of generated `app.js` (~line 230; source at `scripts/render/app-js.mjs:~249`), (2) a second inlined Black-Scholes pricer `stratBsPrice` in the Entry-Strategy engine (`app-js.mjs:~6535`, reusing the same top-of-file `ncdf`), and (3) `lib/greeks.mjs` (imported by `api/portfolio-review.js` — and formerly `js/portfolio.js`, now dormant since #269). This is intentional — `app.js` is a generated single IIFE and can't `import` an ES module. If you change one, change the others. (Note: the "line ~92" reference in `lib/greeks.mjs`'s header comment is itself stale — line 92 of `app.js` is `escapeHtml`.)

The **FedWatch implied-rate math** is duplicated the same way: the server computes the baked probabilities in `scripts/build.mjs` (`fetchFedwatchSnapshot`/`probsFromDelta`/`postMeetingDaysInMonth`/`zqSymbolForMonthKey`), and the browser re-ports the **"now"** pass in `scripts/render/app-js.mjs` (`refreshFomcLive`/`computeLiveFomcBuckets`/`probsFromDeltaLive`/…) to recompute live from `/api/fed-futures` so the widget tracks CME between bakes. Both anchor to the FOMC **target-range midpoint** (not EFFR) and use the same next-month-contract preference + meeting-month inversion fallback. Change one, change the other.

`lib/volume-flags.mjs` is **not** duplicated the same way — it is a single-source module. The intraday volume + support/resistance-break classifier (pure functions, U-shaped intraday-volume curve) is owned by `scan-unusual.mjs`, which precomputes its results into `data/volume-flags.json`. The browser only **renders** that JSON via `MANIFEST.volumeFlags` (`app-js.mjs:~5837` reads it and points back to `lib/volume-flags.mjs` for the rules) — it does not re-implement the classifier. So there is no "change it in both" obligation here; change the math in `lib/volume-flags.mjs` only.

### Yahoo / Gemini quirks the code already handles — don't undo them

- Yahoo's `query1.finance.yahoo.com` rejects raw fetches with `401 Host not in allowlist`. All calls go through `yahoo-finance2` with a desktop `User-Agent` header so the consent-cookie + crumb handshake works. The shared client lives in `lib/yahoo.mjs` for serverless functions and is duplicated at the top of `scripts/build.mjs` for the build.
- The symbol allowlist `/^[A-Z][A-Z0-9.]{0,5}$/` (`lib/yahoo.mjs::SYMBOL_RE`) is what keeps `/api/quote` and `/api/chain` from being used as an open Yahoo proxy. Keep it.
- Beyond `SYMBOL_RE`, the live endpoints clamp numeric inputs as part of the same cheap-allowlist defense — keep these, they stop garbage reaching Yahoo / the RPC: `exp` must be `0..4102444800` epoch-sec (`api/chain.js`, `api/contract.js`), `strike` in `(0, 1e6]` and `side` exactly `call|put` (`api/contract.js`), and `api/close-position` caps quantity `1..100000` / price `0..1e6` before the `close_position` RPC re-validates DB-side.
- `/api/quotes` returns **partial** results: symbols with no Yahoo spot are silently dropped from the `quotes` array (not a 502), because partial data beats failing the whole batch when one obscure ticker disappears from Yahoo. It dedupes + uppercases input and caps at `MAX_SYMBOLS=150` via `.slice(0,150)` (symbols past 150 are dropped, not rejected). Contrast `/api/quote`, which **does** 502 when its single symbol has no spot.
- When Yahoo's `regularMarketPrice` is null and spot falls back to a pre/post-market price, the quote helpers re-derive `change`/`changePct` off `regularMarketPreviousClose` so the displayed spot and the % move share one baseline (`lib/yahoo.mjs::fetchQuote`, duplicated in `api/quotes.js`). Don't pair Yahoo's regular-session delta with a pre/post spot, and keep the two copies in sync.
- FRED's Cloudflare WAF requires a browser-shaped `User-Agent` + `Referer` (see `api/fed-rate.js`). Bare Node fetches return 403.
- Strikes are filtered to ±50% of spot at bake time (`STRIKE_BAND` in both `build.mjs` and `lib/yahoo.mjs`). `fetchContract()` in `lib/yahoo.mjs` deliberately bypasses that band — a held position may sit far OTM/ITM and we need to price it (the live `/api/contract` consumer is the Top Picks tab's "Check a position you hold" tool; keep the bypass, it's a property of `fetchContract`).
- AI calls go through a shared rate-limiter + `data/ai-usage.json` tracker. Don't bypass it from `scan-unusual.mjs` or `refresh-heatmap.mjs` — all three (with `build.mjs`) share the same per-day Gemini budget.

### Supabase: RLS is the security boundary

> **Dormant since #269.** This whole stack backs the Portfolio tab, which was removed from the site (see "Browser runtime layers"). The schema + endpoints are preserved and the rules below remain correct — they matter if/when the tab is re-enabled — but nothing in the shipped page currently exercises them.

Schema lives in `supabase/schema.sql` (run once via the Supabase SQL editor). Three tables: `positions`, `trades`, `portfolio_snapshots`. Two RPCs: `close_position(uuid, int, numeric)` and `delete_trade(uuid)`.

- **Every table has RLS policies scoped to `auth.uid() = user_id`. Never disable RLS** — the anon key is shipped to the browser, so RLS is the only thing separating users.
- The RPCs run `security invoker` so policies apply to them too. `close_position` takes a `for update` row lock before validating, so concurrent closes can't over-sell. `delete_trade` likewise takes `for update` locks — on **both** the trade row and its parent position — to stay race-free against concurrent `close_position` calls.
- Serverless endpoints use **two** clients: a service-role client for JWT verification (`supabase.auth.getUser(token)`) and a JWT-scoped anon client (with the user's bearer token in `Authorization`) for the actual RPC/read, so RLS enforces ownership even server-side. See `api/close-position.js` for the pattern. **Exception:** `portfolio_snapshots` has *only* a `SELECT` policy (`snapshots_select_own`) — equity is server-computed and intentionally not user-writable — so `api/portfolio-review.js` keeps the service-role client past JWT verification and writes the daily snapshot through it (`writeSnapshot(auth.svc, …)`), bypassing RLS. Reads of `positions`/`trades` still go through the JWT-scoped client.
- `api/portfolio-review.js` loads positions server-side from the DB rather than trusting client-supplied positions — a previous version let users poison their own equity snapshot.
- `trades` has **both** a `trades_update_own` policy (`using = own row`, `with check = false` — so `select ... for update` can take the lock while keeping trades append-only) **and** a `trades_delete_own` policy (`using = own row`), the latter added so `delete_trade`'s `delete from trades` passes RLS while running as the caller. See the comments in `schema.sql`.

### Workflow scheduling

There are three data-generating workflows, all triggered **only** by `workflow_dispatch` (no `schedule:` block). An external cron service (cron-job.org) POSTs to the dispatch endpoint at the right ET times. **cron-job.org runs in ET, so it is the single authority on the ET slots and DST** — never replace it with GitHub's `schedule:` (which only speaks UTC and fires twice during DST shifts). The workflows used to re-check the ET hour themselves, but with a `workflow_dispatch`-only trigger that code was unreachable (every firing is a `workflow_dispatch` event), so it was removed; the workflows now proceed on dispatch and trust cron-job.org for timing.

- `daily.yml` — the full bake (`build.mjs`), 8×/trading day: 9:30 ET (open), then hourly 10:00–16:00 ET (the close). Also runs the **AI health alert** step after each build (see `DISCORD_ALERT_WEBHOOK_URL` in the env table — auto-issue on a degraded/down AI layer, auto-close on recovery). Split across two cron-job.org jobs (`30 9 * * 1-5` for the :30 open + `0 10-16 * * 1-5` for the top-of-hour cadence) because one cron line can't mix the two minute values.
- `unusual-flow.yml` — hourly 9:00–16:00 ET; runs **two** steps: `scan-unusual.mjs` then `refresh-heatmap.mjs` (the heatmap's live `ch`/`sp` go stale within a session). Then `regen-static.mjs`.
- `oi-tracker.yml` — twice on weekdays (pre-market ~08:30 ET when overnight T+1 OI lands, EOD ~19:00 ET to light up volume-based signals); runs `scan-oi.mjs`, then `regen-static.mjs`. (The market brief no longer rides this workflow — it's minted hourly inside the bake.)

All three workflows share one `concurrency` group (`stonks-data-commit`, `cancel-in-progress: false`) so they queue instead of committing concurrently — that removes the races on files written by more than one of them (`ai-usage.json`, `heatmap.json`). They still handle landing on a moved `main` differently:
- `daily.yml` does a `fetch + reset --mixed` retry loop because the build wipes and regenerates `data/` wholesale — there's nothing local worth merging from the remote. It restores scanner-owned files (`SCANNER_FILES`) from the remote after the reset so a concurrent scan's output isn't clobbered.
- `unusual-flow.yml` does `stash + pull --rebase + stash pop` because its scanner writes only a few files; a concurrent push from the daily build needs to be preserved.

### Vercel caching

`vercel.json` sets cache headers per route:
- **`/data/(.*)` cache headers are set per-tier by `api/data`, not `vercel.json` (Path B + freemium).** Middleware rewrites `/data/*` to `/api/data/*`, which sets `public, s-maxage=…` for FREE keys (safe + desirable to edge-cache) and `private, no-store` for PREMIUM keys (must **never** be shared/edge-cached — a cached `401` or payload would leak/stale across users). `vercel.json` no longer carries a blanket `/data/*` rule (it can't distinguish free from premium by path glob — the named premium files would need enumerating); the function is the single authority. If you ever reintroduce a `vercel.json` `/data/*` header it must NOT be `public` (it would override the premium `no-store`).
- `index.html` gets a short edge cache and `app.js`/`styles.css`/`js/*` are `immutable` 1-year — these are the gated app **shell + code** (no product data; middleware gates access before the cache serves), so caching them is fine.

The `/api/quote`, `/api/chain`, and `/api/fed-rate` endpoints set their own `Cache-Control` (20–30s edge for live data, 1h for the Fed rate).

## Conventions worth knowing

- **Keep `CHANGELOG.md` current — it is DATED and MONTHLY-ARCHIVED.** Every substantive change (feature, fix, perf, removal, behavior change) gets a one-line bullet in [`CHANGELOG.md`](CHANGELOG.md) **under a `## YYYY-MM-DD` heading for the day the change lands** (create the heading + `### Category` subhead if missing — newest date first, categories in the order Added / Changed / Fixed / Removed / Perf / Docs), as part of the same change — not a separate follow-up. Present tense, plain language, reference the PR (`#NNN`) when there is one. **The root file carries only the current month**: on the first entry of a new month, move ALL of the previous month's dated sections into `docs/changelog/YYYY-MM.md` (same format + the archive preamble) and add that month to the "Older changelogs" index at the bottom of the root file. This is bookkeeping the daily/scanner workflows do **not** automate — scheduled `chore:` refresh commits are not changelog-worthy; only human/Claude-authored changes are. Don't skip it.
- **Render output is committed; `data/` is NOT (Path B).** `index.html`, `app.js`, `styles.css` are committed and pushed by the workflows. **`data/*.json` is gitignored** (anchored `/data/` — an unanchored `data/` would also match `api/data/`) and lives in the private store, served via the gated `/api/data/*`; the workflows push it there, not to the repo. So `data/` files exist on disk locally (run `node scripts/sync-data.mjs pull` to hydrate them for local regen/diagnose) but never commit. Direct hand-edits to `app.js` or `styles.css` will be overwritten on the next build — edit the template strings in `scripts/render/app-js.mjs` / `scripts/render/styles-css.mjs` instead.
- **Reference / legal / info pages are in-app tabs, sourced from [`scripts/render/docs.mjs`](scripts/render/docs.mjs).** The Buyer's manual, Chart patterns, What's included (free-vs-premium), Privacy, and Terms pages were once standalone HTML files; they are now **render-time tabs**. `docs.mjs` exports each page's original `<body>` + its `<style>` (adapted for a shadow root: `:root`/`body` → `:host`, fixed atmosphere overlays → absolute); `html.mjs` emits each as a `.doc-pane` carrying an empty `.doc-host` + an inert `<template>`, and `app.js`'s `mountDocPane` clones that template into a **Shadow DOM** on first tab open — so each page keeps its bespoke styling with **zero collision** against the app's global CSS, but still ships through the normal build (regen-static rewrites `index.html`). The old `/<page>.html` URLs **301→`/?tab=<page>`** via `vercel.json` `redirects`. To edit a page, edit its `style`/`body` string in `docs.mjs` (hand-maintained — no script regenerates it). The lone remaining standalone HTML file is **`welcome.html`** (the Discord OAuth login/denied lander, reached from outside the app).
- **Per-ticker JSON keys are compressed.** Each option row is `{ s, b, a, l, iv, oi, v }` (strike, bid, ask, last, IV, OI, volume). See `compressContract()` in `lib/yahoo.mjs` and `scripts/build.mjs`. The browser code expects this shape. The container around the rows is `data/<SYM>.json.chains` — an object keyed by the **stringified epoch-second expiration**, each value `{ c: [...calls], p: [...puts] }` whose elements are those compressed rows (`build.mjs` ~2295). The browser reads `chain.c` / `chain.p` throughout `app-js.mjs`.
- **Expirations are epoch seconds.** Used as keys throughout (`data/<SYM>.json`, `positions.expiry`, `/api/chain?exp=...`).
- **Graceful degradation is everywhere.** Yahoo flake → skip that ticker, don't fail the build. Gemini flake → reuse last-good narratives and mark them stale. FRED flake → fall back to `FALLBACK_RISK_FREE_RATE`. Single-position pricing error in the portfolio review → that row degrades, the rest of the review still ships. Preserve this pattern.
- **No bundler.** All browser ESM imports use jsdelivr CDN URLs (`https://cdn.jsdelivr.net/npm/<pkg>/+esm`). Adding a new browser dependency means importing it from the CDN, not adding to `package.json` (which is for build/server deps only).
