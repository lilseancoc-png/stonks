## 2026-07-21

### Added

- **Sector Rotation: a premium rebound desk for quality companies sold with their group, then beginning to recover.** Each bake writes `data/sector-rotation.json` from the fundamentals, grades, daily bars and company-news judgment already collected for the covered universe — no extra market-data calls. The screen requires business quality, measures whether the drawdown is shared by the relevant peer complex, refuses to label material company-specific deterioration as “rotation,” and classifies each setup as washed out / first thrust / confirmed / late (a first thrust waits for a pullback instead of being chased). The new `rotation` tab adds an idea-funnel summary, deterministic underlying trigger / invalidation / first-target / reward-risk levels, ticker deep links and live quote context; its JSON is ordinary premium (not role-hidden) and the home card, sidebar, command palette and feature matrix expose the new desk consistently. `scripts/build.mjs`, `scripts/regen-picks.mjs`, `lib/premium-keys.mjs`, `scripts/render/{html,app-js,styles-css,docs}.mjs`.

- **News desk: a straight-news triage queue for the entire covered universe.** Each bake now preserves the current linked per-ticker headline slate before AI-cache reuse, merges it with the market-wide sources behind Briefs, and writes a compact free `data/news-feed.json`. A deterministic classifier ranks likely materiality (high impact / notable / context), keeps favorable/adverse/mixed direction separate, flags unconfirmed wording, deduplicates corroborated coverage, and shows the stock's already-active tape without claiming the headline caused it. The new lazy-loaded tab adds impact/search/scope/direction/sector/category/age filters, impact-vs-latest sorting, ticker deep links, and a dense responsive feed. `lib/news-feed.mjs`, `scripts/build.mjs`, `lib/premium-keys.mjs`, `scripts/render/{html,app-js,styles-css,docs}.mjs`.

### Changed

- **The freemium tab split now puts Earnings Calls, Narratives, and Index Calendar in the free tier, while Trending IV and Streaks move to premium.** The server key policy, narrative manifest sidecar, client locks and home-card badges, and the in-app feature matrix all use the same split. `lib/premium-keys.mjs`, `scripts/render/{app-js,html,docs}.mjs`, `app.js`, `index.html`.

## 2026-07-20

### Added
- **Leveraged ETFs: the page becomes a trader-first execution desk** — a top summary separates enter-now setups from waits and risk-flagged ideas, with entry-status/direction filters plus conviction, setup-quality, estimated-R:R and reset-drag sorts. - **Quant Lab: regime conditioning** — every bake now classifies the tape on four regimes (volatility: VIX level/term + SPY 20d realized vol; trend vs range: SPY 60-session efficiency ratio + monotone higher-highs/lower-lows thirds; risk-on/off: the Market Analysis tape, which is why the quant step in `main()` moved after `computeMacroRegime`; earnings-heavy vs quiet: share of the universe reporting inside ~2 weeks) and picks each screen's badge bars from a fixed per-regime table: sigma "extreme" needs 2.5σ Bollinger / 3σ return in strong trends or high/crisis vol (vs 2/2), VRP rich/cheap needs |z| ≥ 2 in high vol (vs 1.5), the pair "stretched" read widens to 2.5σ in high vol and tightens to 1.75σ in calm range-bound tape, and term-structure inversions are down-weighted through earnings-heavy/high-vol stretches (plus a per-name "earnings" badge when the print is inside ~5 weeks — event vol loading the front is expected, not stress). Rows are never hidden by regime — only badged and re-ordered — and a chip strip at the top of the tab shows the regime states, inputs and bars in force. `buildQuantRegime` in `scripts/build.mjs` (exported, offline-degrades per axis), render in `scripts/render/{app-js,html,styles-css}.mjs`, spec in `docs/quant-lab.md` §2.
- **Quant Lab: pairs methodology rework** — the pair spread is now the properly hedged lnA − β·lnB, with β from a one-year **Engle-Granger** regression (`quantEngleGranger`, exported: OLS + ADF(1) on the residual vs the MacKinnon 5% bar → a "cointegrated" badge; under ~200 joined sessions the raw log ratio remains as a labeled fallback). Each pair now reads on two horizons (60d and ~1y z + AR(1) half-life — some pairs only mean-revert on one), carries a rolling hedge-ratio drift check (β on the trailing 120d vs the 1y ratio, warned at ≥25% drift), a correlation-stability badge (corr ≥ 0.5 must also hold on the 60d and 1y windows, not just the 120d gate), and a factor match grade (SPY-beta / size / momentum gaps + a $25M avg-dollar-volume liquidity floor → good/fair/poor). Deliberately NOT added: Johansen (adds nothing for 2-asset pairs), Kalman-filter hedge ratios (un-auditable tuning knobs — rolling OLS instead), multi-year windows (priceSeries carries ~1 year) and stock-borrow screens (no data source) — all disclosed on the coverage card. `scripts/build.mjs`, `scripts/render/app-js.mjs`, `docs/quant-lab.md`.
- **diagnose-pairs harness: regime + cointegration validation** — the pair-convergence backtest now splits entry events by the retro regime at entry (SPY trailing RV20 vol buckets + ER60 trend/range — VIX isn't persisted per-day, disclosed) so the "mean-reversion works best calm/range-bound" conditioning claim is testable; a new hedged-spread walk (daily re-estimated no-lookahead EG β, frozen at entry) splits convergence by the cointegration badge; and the VRP rich-side stats split by vol regime. `scripts/diagnose-pairs.mjs`.
- **Quant Lab: "Aggregate ideas" confluence screen** — a new table at the top of the tab cross-referencing four independent flow screens the site already computes: the session's largest unusual-options prints (top 10 by this-hour premium, the Unusual tab's "Top print" basis), the top intraday volume flags (best hourly/EOD ratio, confirmed S/R breaks included), fresh ≤3-session price streaks, and 5-day rising / surging IV (Trending-IV's own tier/ramp/streak bars). ### Fixed
- **Quant Lab and every premium feed now survive Vercel's split-function session loss.** Production traces showed the signed-in `/api/auth/me` probe succeeding while the adjacent `/api/data/quant.json` request returned `401 auth required`; the attached 72 KB Quant payload itself renders cleanly. Once the gate is confirmed, all data loaders now read through a data mode on that exact working `/api/auth/me` function. Both it and `/api/data/*` delegate to new `lib/data-response.mjs`, preserving the same key validation, free/premium split, stricter role claims, cache policy, and private-store reader; the datastore is dynamically imported so ordinary auth probes stay lightweight. Legacy cached bundles are covered by a same-origin `307` from `/data/*` to the same route. Quant also sends credentials explicitly and surfaces the actual HTTP/parse error instead of the old generic message. Flag-off deployments still use static `data/*`. `lib/data-response.mjs`, `api/{auth,data}`, `middleware.js`, `scripts/render/app-js.mjs`.
- **Lazy tabs no longer pin a failed data fetch for the whole page session.** A tab data fetch that failed (e.g. the Quant Lab 404ing before its first-ever bake on launch morning) cached `{ loadError: true }` without a `fetchedAt` stamp, and both refetch guards — `tabDataStale` (which treats an unstamped state as fresh) and the simpler `if (state.data)` gate on the earnings-tracker / earnings-calls / AI-CapEx / RAM-prices / capital-raises / IPOs-&-credit loaders — then blocked every retry, so the error card stuck until a full page reload even after the data came alive. Error states are now always considered stale, so re-entering the tab retries the fetch. The Quant Lab's empty card also distinguishes a failed load ("Could not load…") from data that genuinely hasn't been baked yet, matching the other tabs. `scripts/render/app-js.mjs`.
- **Earnings calls: a runaway transcript brief no longer re-burns full-model tokens every bake.** Some calls (UBS every bake since 2026-07-17, CAT intermittently) made `gemini-3.5-flash` enumerate until output hit the 16,384-token cap, truncating the JSON — the parse failure left no marker, so the same name re-attempted every bake (~13.6k in + ~16.4k out tokens, 8×/trading day, forever) and wasted one of the 6 summarize slots each time. Three-part fix in `summarizeEarningsCall`/`updateEarningsCallsData` (`scripts/build.mjs`, same path as `regen-transcripts.mjs`): the response's `finishReason === "MAX_TOKENS"` is now detected up front and — like malformed-JSON/missing-section rejects — tagged as a deterministic CONTENT failure; content-failed names get a persisted per-name daily cooldown (a `fails` map in the index, the AI-side sibling of the 3-day probe cooldown — one retry per ET day, self-pruning on the date roll; transient API failures still retry next build); and the runaway itself is tightened with `maxItems` bounds on every array in `TRANSCRIPT_SUMMARY_SCHEMA` (matching the normalizer caps that would drop the overflow anyway) plus a be-selective instruction in the system prompt. Graceful degradation preserved — a failed name renders its prior brief and the build never fails.
- **IPOs & credit: quarter chips render as "Q2 '26" again.** `icQtrShort`'s regex was written with a single-backslash `\d` inside the app-js template literal, so the shipped code matched nothing and every short quarter label fell back to the raw "2026Q2" key. `scripts/render/app-js.mjs`.
- **Earnings tracker: the "Heading into earnings" strip's columns now line up in every row.** Each row is its own CSS grid, so the drift column's `max-content` track resized per row — a wide 2-week sub-value ("-26.5% 2wk") squeezed the name column and shifted that row's trend chip and report date a few px left of its neighbors. The value track is now pinned (`minmax(62px, max-content)`), so chip / date / drift sit on identical tracks across all rows. `scripts/render/styles-css.mjs`.
