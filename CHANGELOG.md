## 2026-07-08

### Changed
- **Top Picks: the "Buy now" call is now MULTI-FACTOR — a weighted entry-readiness checklist, not just "wait for a pullback price".** `computeEntrySignal` previously read buy-now only on a textbook timing-gate `go` (momentum + a pullback to the 20D SMA or a volume spike); everything else was parked behind a trigger price, so a steadily-trending, multi-confirmed name could idle un-enrolled behind a dip that never filled. Now, after the hard vetoes (imminent earnings/macro event, an `avoid` knife/chase state, and the wrong side of the 20D SMA — all still absolute), a weighted checklist decides: momentum alignment (MACD + RSI, ×2), right side of the 20D trend, healthy pullback location, confirming volume, a ≥ +1% 3-day thrust off confirmed closes, the 20D/50D SMA stack, and strong-tier conviction — minus penalties for an extended stretch > 4% past the 20D and a tape that fights the trade. Clearing `PICKS_ENTRY_READY_BAR` (default 4, env-tunable) = buy-now, so a confirmed breakout can also overcome the extension penalty instead of being forced to wait for a pullback. A confirmed `go` stays a buy-now unchanged, and the checklist ships on each scored entry (`entry.checks` + `entry.readiness`) so the card can show why. This also widens the track-record enrollment gate (`entry.signal === "buy-now"`) to the same multi-factor read. `scripts/build.mjs`, `scripts/picks-smoke.mjs`, `docs/top-picks.md`, `CLAUDE.md`.

### Perf
- **Gemini cost: the ticker-judgment cache now tolerates headline churn — a build whose only news delta is ≤1 genuinely-new headline title reuses the cached judgment instead of re-reading.** Yahoo's top-10 news list turns over intraday (one new SEO piece busted the exact-match key), which held intraday reuse to ~20% — ~110 fresh Flash-Lite calls (plus their article body-fetch waves) per hourly bake for takes whose substance hadn't moved. Price-moving news still forces a re-read via the existing 2% spot-drift guard, fundamentals/model/date changes still bust the key outright, and new-title counts accumulate against the original cached title set so a drip of articles re-reads once it crosses the tolerance. Tunable via `AI_TICKER_CACHE_NEWS_TOLERANCE` (0 restores exact-match-only). `scripts/build.mjs`, `CLAUDE.md`.
- **Gemini cost: the chart-pattern detector no longer re-rates frozen charts — cache entries carry a bar-series signature, and unchanged bars reuse the cached read across AM/PM bucket rollovers.** The intraday bars are regular-session only, so every weekend/evening/holiday run was re-reading ~139 byte-identical charts on the full-Flash vision model (the priciest per-call spend in the build, ~$0.29/pass with its thinking budget); those runs now reuse for free with zero freshness trade-off — any new session bar changes the signature and re-reads as before. `scripts/build.mjs`, `CLAUDE.md`.
- **Gemini cost: the per-article body cap fed to the ticker-judgment prompt is now env-tunable (`AI_ARTICLE_BODY_CHARS`, default unchanged at 3000 chars)** — bodies are the bulk of that pass's input tokens, so spend can be trimmed without a deploy. `scripts/build.mjs`.

### Fixed
- **Grade tab: the Earnings-history card no longer strands a ticker on year-old prints (ORCL showed nothing newer than Jun 2025).** Yahoo's visualization feed froze in mid-2025, so a ticker whose first-day Nasdaq fallback fetch flaked was left with 8 EPS-complete but ancient rows — which the backfill's depth + EPS checks read as "done", so the recent quarters were never fetched again. `earningsBackfillNeeded` now also re-triggers (once per ET day) whenever the newest stored print is older than ~110 days, so every stranded name keeps retrying the Nasdaq surprise backfill until the recent quarters land. Also fixes the bogus uniform "IV post" column: `earningsIvAround` now only accepts iv-history samples within 7 days of the print (events predating iv-history coverage were all stamped with the store's first-ever sample), and a one-time store repair clears the poisoned `ivPre`/`ivPost` stamps (live pre-print `ivPre` snapshots are kept) so the guarded pass re-fills them where a real nearby sample exists. `scripts/build.mjs`.

## 2026-07-07

### Added
- **Track Record: the Simulator is now a full portfolio BACKTESTING ENGINE — one flexible $100k replay of the Top Picks record with four selectable sizing run modes.** Shared realistic portfolio rules across every mode: positions sized from *max loss* (credit spreads: width − credit, never the credit received), contracts rounded down so a trade can never risk more than 2% of current equity; total open risk ("heat") capped at 20%; max 20 concurrent positions and 4 per sector; a correlation gate that skips a third same-sector, same-direction trade once heat is elevated (≥70% of the cap); and a rotation rule — a heat-blocked new pick may free room by closing one existing winner held >5 days that has been up ≥+20% on premium (banked at +20%), else it is skipped. The run modes: **Fixed sizing** (Very High conviction = full 2% single tranche; High conviction ladders 1% + a second 1% added mid-hold only after the option confirms ≥+10%, filled at the confirmed price), **Volatility targeting** (conviction base 2%/1.5% scaled by average entry IV ÷ the trade's entry IV), **½ Kelly** (conviction base × a Half-Kelly multiplier computed *walk-forward* per conviction bucket from resolved per-contract stats — no lookahead; buckets under 10 resolved trades fall back to the base), and **Vol × Kelly** (both adjustments compounded); every formula mode clamps final risk into 0.75–2%. The pane adds a run-mode selector, an all-four-modes comparison table on the same trades, per-mode chips (avg risk %, peak heat, winners rotated, ladder adds, skip reasons) and a Kelly-inputs-by-bucket table; Monte Carlo now also compounds on the $100k base. `scripts/render/app-js.mjs`.
- **Track Record: every sub-tab now opens with an "At a glance" summary strip — the view's key numbers plus a one-line takeaway, before the detail.** Summary leads with the health verdict / win rate / profit factor / per-risk expectancy and how many diagnostics are firing; Scorecard adds the breakeven read (does the current win rate clear the reward-to-risk bar?); Top 10 shows the roster's side split, this refresh's in/out churn and the forecast lean; Activity totals the grade-move balance + conviction-bar crossings and names the most recent event; Picks leads with the open book's average modeled mark and the resolved W–L record; Equity, Simulator and Monte Carlo surface their bottom lines (cumulative P&L / drawdown state, simulated return, median outcome + probability of profit); Breakdowns calls out the strongest and weakest bucket across its tables. All deterministic, computed from the same data each pane renders; strips hide while a pane has no data yet. `scripts/render/{app-js,html,styles-css}.mjs`.
- **Top Picks: a SHARED watchlist — save any pick and the idea stays put through every roster refresh until someone removes it; one list for everyone.** Each pick tile gets a ☆ star (the detail page a real "☆ Watchlist" button); saved ideas render in a pinned "★ Watchlist" group above the roster. Anyone with access to the tab can add or remove; the list persists server-side via the new `/api/watchlist` endpoint (GET / POST add|remove) under the request-time-owned store key `picks-watchlist.json` — the pick snapshot is sourced server-side from the store's `picks.json` (clients send only symbol+side), access mirrors `picks.json`'s gating (session + fail-open `tp` claim), and the workflows never push or delete the key (`REQUEST_TIME_EXCLUSIVE` in `sync-data.mjs`, so a mid-bake toggle can't be reverted by the flush). While a name keeps shipping the saved card tracks the live roster ("● in today's picks"); once it drops off the last snapshot freezes ("⏸ off today's list") — still openable as a full judgment page — until removed. Capped at 30 entries; degrades to a per-browser `localStorage` list when the endpoint is unreachable (gate off / signed out). `api/watchlist.js`, `scripts/sync-data.mjs`, `scripts/render/{app-js,styles-css}.mjs`, `docs/private-data-migration.md`, `CLAUDE.md`.

### Changed
- **Track Record: a pick now only enrolls in the track record when its entry call is a clean "✅ Buy now" — and the accumulated record was reset.** A wait-state pick (⏳ wait for a 20D reclaim / pullback / dip trigger, or an earnings/event defer) is advice to hold fire, not a filled trade, so grading it from the roster print scored trades the engine told the user not to take yet; it now stays on the roster un-enrolled and enters the record on the first hourly bake where its trigger has hit and the entry signal flips to buy-now. Because the old record blended wait-entry trades with the new rules, the stored track record (open book + closed history + stats) is wiped once via a new `PICKS_ACCURACY_RESET_EPOCH` stamp in `build.mjs` — a stored `picks-accuracy.json` from an older epoch is discarded on the next bake's read (the creds-free equivalent of `wipe-history.mjs`; bump the constant for future resets). `scripts/build.mjs`, `docs/top-picks.md`, `CLAUDE.md`.
- **Top Picks: the "✅ Buy now / ⏳ Wait $X" entry call is now LIVE while the tab is open.** The 30-second quote poll the tab already runs re-checks every wait chip's own trigger against the live price and flips it in place: a *pullback/dip* pick whose price reaches the trigger flips to a pulsing green **"✅ Buy zone now"** (that price IS the plan's entry), while a *20D-reclaim* pick that crosses intraday arms an amber **"⚡ Hit $X — confirm close"** (the thesis needs a confirming daily close, same no-look-ahead rule as the timing gate). Earnings/macro-event defers are never overridden, already-buy-now chips are left alone, and the chip restores its baked state the moment price backs off — the hourly build re-bakes ground truth either way. Works on the grid tiles, the pick detail card, **and saved watchlist cards** (watchlist symbols — including frozen off-roster snapshots — now ride the same quote poll, so a saved "wait" idea lights up when its price hits). `scripts/render/{app-js,styles-css}.mjs`.
- **Top Picks: a debit vertical must now pay at least 1x its risk or it is never recommended.** `pickVerticalForPick` rejects any debit-spread candidate whose reward:risk (`maxProfit/maxLoss`) is under the new `PICKS_DEBIT_MIN_RR` floor (default 1.0 — the net debit can never exceed half the strike width), mirroring the credit side's `PICKS_CREDIT_WIDTH_FRAC_MIN` floor; a name with no qualifying spread falls down the existing structure ladder (naked long) or ships without a contract. Env-tunable via `PICKS_DEBIT_MIN_RR`. `scripts/build.mjs`, `scripts/picks-smoke.mjs` (+2 checks), `docs/top-picks.md`.
- **Switching tabs now pushes a real browser-history entry, so the Back button walks back through the tabs you visited instead of leaving the site** — landing from Google and clicking around no longer means one Back press bounces you straight out. Restoring state never mints an entry: the boot-time deep-link resolve and the back/forward (`popstate`) handler sync the URL with `replaceState`, re-clicking the active tab is a no-op (unchanged-URL guard), and within-tab URL mirroring (the Grade tab's `?s=/exp=/k=/t=` contract params) keeps replacing in place so flipping through strikes doesn't flood history. `scripts/render/app-js.mjs`.

- **Market tape is now a weighted composite — heavyweight factors (Fed path, credit, VIX, the indexes themselves) move the regime more than slow or derivative ones (monthly CPI, rotation, the F&G composite).** Every axis's −2..+2 vote is scaled by a per-axis weight (`MACRO_AXIS_WEIGHTS`: indexes ×1.5; fed/credit/vix ×1.25; yields/2Y/global-tape/breadth ×1.0; dollar/MOVE/commodity/geo/put-call ×0.75; inflation/sentiment/rotation ×0.5) in **both** the net-stress sum and the effective (cluster-discounted) axis counts — in a cluster the heaviest lit axis counts at full weight, extras at the discount × their weight, so with all weights at 1 the math reduces exactly to the old flat vote. Weights are env-tunable per axis (`PICKS_MACRO_AXIS_WEIGHTS="fed:1.5,inflation:0.25"`), ship in the thresholds sidecar so the browser's live re-port weighs identically (pre-weights baked payloads degrade to the flat vote), and surface as a ×w chip on each axis tile. - **Market tape: a standing hot-CPI vote can no longer lock the tape risk-off against a green board.** With CPI 4.2% YoY re-accelerating, the inflation axis is a mechanical −1 every build for months (its re-accel test compares a 3-month-ago baseline), so under the count-only gate ANY second −1 anywhere — today a +0.8bps yield day riding a 5-day trend — read the whole tape risk-off while 8 axes voted risk-on at net stress +7. Two changes, both replayed against the recovered May–Jun window with zero regressions on the real risk-off days: (1) the inflation axis joins the **rates cluster** in `MACRO_AXIS_CLUSTERS` — a hot CPI's equity impact transmits through the Fed path / yields / dollar the tape already reads live, so counting it as an independent axis double-counts one tightening story (the Jun 10 4.5% print confirmed this: SPY −1.6% print day, +1.7% next, all captured by the fast axes); (2) the plain risk-off gate now also requires **net stress ≤ 0** (`PICKS_MACRO_RISKOFF_STRESS`, env-tunable) so a two-axis count trip can't override a broadly positive board — severe-risk-off keeps its own stricter stress gate and is untouched. Today's tape reads neutral under the new gate (not risk-on — CPI hot + yields rising still dissent), and a genuine deterioration (VIX 22 rising + indexes breaking down) still trips severe immediately. Mirrored in the browser's live re-port (`computeLiveMacroRegime`; `riskoffStress` ships in the thresholds sidecar, falling back to 0 against a pre-change baked payload). `scripts/build.mjs`, `scripts/render/app-js.mjs`, `docs/top-picks.md`.

### Fixed
- **Credit-spread exit ladder no longer anchors "Take profit" at the expiry breakeven.** For a credit vertical (e.g. a SPOT $460/$430 bull put spread) the ladder's take-profit rung sat at the expiry breakeven (short strike − credit, ~$450) — a level on the ADVERSE side of entry where the position is at best flat at expiry and marked at a loss before it, shown alongside the $460 "defend & cut" rung. The rung now anchors at the delta-estimated FAVORABLE move that would collapse the spread's buy-back price to the +50% target (theta gets there with no move at all — the rung prose spells out that the real trigger is the spread's buy-back price while spot holds beyond the short strike), and the expiry breakeven moves to the "Also exit if" context lines. Also fixes the Top Picks live board's "✓ Target hit" chip, which fired instantly on every credit spread (the old TP level was already crossed at entry), gives the live chips credit-spread-aware wording (short-strike breach / confirm the buy-back price before closing), and hardens the Track Record open-row TP/cut chips against a null level (`Number(null)` is 0 — it rendered "TP $0.00"). `scripts/build.mjs` (`buildCreditExitPlan`), `scripts/render/app-js.mjs`, `docs/top-picks.md` (#540).
- **`g.theta` → `g.thetaDay` — the contract quality score was NaN everywhere.** `lib/greeks.mjs` returns `thetaDay`, but the contract selectors read `g.theta` (undefined) at four sites, so the composite quality ranking silently degraded to "first row that passes hard filters", the `PICKS_MIN_QUALITY` floor never rejected, every shipped contract's `thetaDay` was null, and the track record's theta stop could never fire. One-word rename; quality ranking, the 0.45 floor, the theta screens, and the theta stop are all live again.
- **Earnings-day guards no longer switch off on the print day.** Date-only earnings dates were compared via `Date.parse` (midnight UTC ≈ 8pm ET the *prior* evening), so on earnings day itself the entry-timing defer, `selectStrategy`'s 21-day gate, the contract-level `earningsInWindow`, the tracker's pre-earnings exit, enrollment skip, and the brief watchlist's "earnings imminent" all treated the print as past — the engine could recommend a naked long or credit spread hours before an AMC print. All seven sites now use an ET calendar-day diff (`etDaysUntil`; 0 = print day, still ahead).
- **The streak signal is live in production bakes.** `main()` passed `streaksMap = null` into both scoring calls, so the Technicals "streak ±1" signal never fired in any baked `picks.json`/`grades.json` while `regen-picks` (which reads `streaks.json`) scored it — the two paths could grade the same data differently, flipping names across the conviction bars. The bake now feeds the freshly-built streaks map to both.
- **Track record: unmarkable positions resolve `void` on every exit path** (previously only `dropped` had the void escape — a position that couldn't be marked at timeout/expiry/reset booked a phantom loss), the stats layer's `pnum(null)`-passes-as-0 filters no longer count null-P&L rows as 0% option wins or average null open marks as 0%, a failed mark with chain data present carries the last good mark forward instead of nulling it, a vertical leg that fails to price makes the spread unmarkable instead of being valued at $0 (which fabricated ≥+100% credit-spread "wins" and −100% debit "losses"), and the trail-stop's peak fallback uses an explicit null check.
- **Timing/IV penalties can no longer flip a grade to the opposite side.** Entry-timing and IV-cost contributions are computed for the provisional (pillar-implied) side; when they crossed `total` through zero the engine shipped an opposite-side grade whose conviction was manufactured entirely by a penalty computed for the other direction (e.g. net-bullish pillars + a falling-knife penalty ⇒ "high-conviction Put" with all-bullish drivers, leaking into `grades.json`, the grade-change log, `grades-daily`, and the churn events — and filing call-side timing under both `timing.call` and `timing.put`). `total` now clamps at 0 instead of crossing.
- **`buildTopPicks` walks candidates with per-group fill counters** instead of a combined 16-push break — a watch-heavy top of the ranking can no longer starve actionable candidates that ranked below it, and surplus actionable names no longer consume sector/factor/side caps for picks that were then sliced off (which mis-attributed exclusions in `rosterMeta`).
- **`rosterMeta.book.netDeltaPct` reports real net directional exposure** — it was hardcoded `delta * 0` (an all-call and an all-put book both reported 0). Now sums each position's signed dollar-delta (contract Δ × 100 × contracts × spot) as % of the display account.
- **Expiry-day marks keep the remaining session's time value.** `lib/greeks.mjs::yearsToExpiry` now adds the same ~20h close offset the client applies (`EXPIRY_CLOSE_OFFSET_MS`) — the tracker was pricing expiring positions at ~intrinsic a full session early.
- **Unusual flow can flag a contract's first burst.** A contract absent from the prior in-session snapshot of a *covered* symbol now gets a ~0 baseline (it was below the history's vol-50 floor) instead of "unknown" — previously a 0→10,000-volume hour, the archetypal informed block, structurally could not flag on its burst hour. A symbol whose whole fetch failed last scan stays unknown (no false flags). Also mirrors scan-oi's `!attempted` abort guard.
- **Grade/churn history logs survive coverage gaps.** `diffGradesHistory` carries baselines forward for symbols missing from a build (Yahoo flake / ≤25% tolerated misses) instead of erasing them — a one-build gap no longer loses real grade changes or fires a phantom "entered" churn event when the name returns unchanged.
- **Roster badges: "new" vs "entered" were swapped** relative to the client's definitions — genuinely new coverage showed "entered" while a returning already-tracked name got ★ NEW. The predicate now tests prior-grade existence, and `buildPickForecast` normalizes to the pick's *held* side (a stale-reused roster whose grade flipped no longer forecasts the opposite trade).
- **`diagnose-pick-losses.mjs` can model picks again** — it required `exitSpot`, a field the tracker never wrote; closed records now stamp `exitSpot` and the diagnostic falls back to `lastSpot` for older rows. `diagnose-grade-ic.mjs` no longer turns a null forward close into a fabricated −100% return (one such row swamped a day's IC and decile spread).
- **Gamma rule 5 no longer scores week-old flow as "today's".** `scan-oi` bounds `unusual.json` staleness (≤4 days) and labels the signal "recent flow"; `computeEntryTiming`'s macro-event defer honors `PICKS_TIMING_EVENT_DEFER_DAYS` instead of a hardcoded 5.
