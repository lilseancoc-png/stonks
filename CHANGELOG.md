## [Unreleased]

### Changed
- **Top Picks — horizon-aware pillar weighting (`PICKS_HORIZON_WEIGHTS`, default on).** The score is a stock-picker's 4-pillar grade, but the product trades ~14-day long premium on 30–60 DTE contracts — a horizon mismatch. Over a fortnight a name's move is dominated by order flow + price structure + the tape, while the **fundamental** pillar (EPS/revenue growth, P/E, FCF, net-margin) pays off over quarters and is ~fully priced over the hold; equal-weighted it was the largest-magnitude pillar and dominated the grade with signal a 2-week option can't monetize. Each asset-quality pillar is now scaled by a **horizon weight** before summing — Fundamentals **0.6** (`PICKS_HW_FUND`), Technicals **1.0** (`PICKS_HW_TECH`), Mechanicals **1.15** (`PICKS_HW_MECH`, order flow leads price), Narrative **0.9** (`PICKS_HW_NARR`); `timing`/`ivCost` ride ×1. A principled microstructure prior (flow ≳ technicals ≫ slow fundamentals at 1–3 weeks), **not** a fit to the 19-pick sample — the per-signal IC bridge stays the path to measured weights. Applied in both `scorePillared` and `computeCrossSectionalScores` via `applyHorizonWeight`, which bakes the weight into each signal's `contribution` so the card chips stay consistent with the weighted pillar total (raw integer `score` and the IC-bridge `z` untouched). Percentile tiers self-recalibrate, so the actionable count is unchanged — it re-ranks (RDDT +8.6→+4.9, LLY +11.0→+8.2, banks pulled down; names whose bearish grade rested on weak fundamentals pulled toward zero). Expect a one-time grade/roster shift on the next bake; `PICKS_HORIZON_WEIGHTS=0` reverts to the byte-identical legacy equal-weight sum (verified 0/138 grades differ).
- **Top Picks — severity-scaled knife/chase penalty (`PICKS_TIMING_AVOID_SCALE`, default on).** The entry-timing `avoid` penalty was a flat −8, which let the *most egregious* setups (a +50% five-day blow-off, a −15% one-day collapse — the biggest historical losers) still clear the conviction bar when the four-pillar grade was high (`|subtotal| − 8` can stay above ±12). The penalty now **scales past −8 by severity** — `max(PICKS_TIMING_AVOID_FLOOR=−16, −8·severity)`, where `severity` = how many multiples of its own trigger the worst firing read is (a +50% run is 5× the 10% chase trigger; a −15% drop is 2.5× the −6% knife trigger) — so the worst chases/knives are fully neutralized to a no-trade on their own. A borderline `avoid` (severity 1, right at the trigger) still gets exactly −8, so it's a strict superset of the old behavior; still one number folded into `total` (no separate veto). Expect a one-time grade/roster shift on the next bake (some extended names that previously squeaked on now drop off); set `PICKS_TIMING_AVOID_SCALE=0` to revert to the flat −8.

### Added
- **Calendar — rest-of-year horizon, promoted to its own top-level tab, grouped by month.** The calendar now spans every dated event from today through **December 31** (was a fixed 30-day window) and is its own top-level nav tab (pulled out of the *Macro* dropdown) for clarity. A new `calendarCutoffMs(startMs)` helper centralizes the window — end-of-current-year, with a 30-day floor so a late-December window still spills into January — and replaces every `CALENDAR_DAYS_AHEAD` arithmetic site in `scripts/build.mjs` (`buildCalendarPayload`, the stale-report salvage, the catalyst validator, `main()`) and `scripts/regen-calendar.mjs`. The full monthly macro-release schedule (CPI/PPI/NFP/JOLTS/unemployment) and all remaining FOMC meetings now surface; per-ticker earnings still contribute each name's single confirmed next print (Yahoo's only forward date). Catalyst extraction is widened to the same horizon (prompt + deterministic validator) and the per-ticker cap is raised **3 → 5**. The browser timeline (`renderCalendar`) now buckets events into **month sections** with a **sticky month header** (name + event count) and, when the window spans more than one month, a **month jump-nav** that smooth-scrolls to each section; the eyebrow shows the window end ("… · through Dec 31, 2026") when present. Payload gains `windowEnd` (+ `windowDays` is now the actual span, not a constant); old `calendar.json` without it renders fine (no through-date shown). The Nasdaq AM/PM session fetch now pulls **only the distinct dates curated tickers report on** (passed explicitly) with bounded concurrency (8) instead of walking ~150 weekdays of the longer window. The committed `data/calendar.json` refreshes to the full rest-of-year set on the next scheduled bake.
- **Calendar — Polymarket "will they beat?" reading on earnings chips.** Each earnings event now carries a best-effort **market-implied earnings reading** from Polymarket when an open market for that company resolves near the report date — preferring a beat/miss/EPS-estimate market (so the pill answers "will they beat?") and falling back to the highest-volume earnings market (labeled by its own question) otherwise. Rendered as the same `cal-report-pm` pill the macro-report rows use (platform · question · % · `thin` liquidity tag · link to the source market), stacked under the chip head. New `fetchEarningsPrediction()` + `upcomingEarningsList()` in `scripts/build.mjs` write a per-event `predictions[]` into `data/calendar.json` keyed by `SYMBOL|date` (also wired into `scripts/regen-calendar.mjs`); the matcher gates on company long-name (`fundamentals.name`) + earnings keyword + ±`PM_EARNINGS_NEAR_DAYS` (21) date proximity. Free public reads — **no API key** — and it degrades silently (most tickers match nothing; Polymarket only lists earnings markets for a few mega-caps in season). Display-only — it does **not** feed the picks/event-risk gate (earnings already have their own pre-print entry defer). Tunable via `POLYMARKET_EARNINGS_TAGS` / `PM_EARNINGS_NEAR_DAYS`; the egress allowlist blocks Polymarket from the dev sandbox, so the parsing is written against the documented Gamma shapes and verified on the first real bake.
- **Top Picks — IV cost as a dedicated scoring term, not just a gate (`PICKS_IV_SCORE`, default on).** The engine grades like a stock-picker but trades short-dated long premium, where IV richness is first-order (right on direction, wrong on vol = a crush loss). Previously a name's own IV rank only nudged the bounded −8..+4 entry-timing budget, so two names with the same direction/quality but very different own-IV ranks scored ~the same and ranked next to each other. Now `computeIvCostContribution` folds a **continuous, direction-agnostic conviction cost** into `total` alongside timing (a 6th component, sibling to `timing`): centered at the name's own median IV (rank 50), above → penalty (to −`PICKS_IV_SCORE_MAX`=3 at the richest), below → credit (to +`PICKS_IV_SCORE_CHEAP_MAX`=1.5 at the cheapest, asymmetric so richness costs more than cheapness rewards). It weakens/strengthens conviction for whichever side, never flips it — so of two otherwise-equal setups the one whose vol is cheap relative to its own history ranks ahead (you're not paying up into a crush). Renders as its own "IV cost" row in the score breakdown (Top Picks + grade-any-ticker). To avoid double-counting, when on it **owns** the rich/cheap magnitude — the legacy in-timing soft con/pro is suppressed, while the ≥90th-percentile veto stays as a pure go-block. Excluded from the per-pillar grade-change/roster accounting (like `timing`); reads real own-history IV rank only (no RV proxy). Expect a one-time grade/roster shift on the next bake; set `PICKS_IV_SCORE=0` to revert to the legacy in-timing nudge.
- **Calendar — prediction-market cross-check upgrades (divergence + liquidity + trend).** The FOMC widget's Kalshi/Polymarket block now (1) flags a **consensus divergence** (`⚠ sources disagree · Npt`) when the ZQ-futures, Kalshi, and Polymarket odds split ≥10 points on a bucket — that's where one source is mispriced; (2) shows each platform's **traded volume** and a **`thin` tag** that de-emphasizes low-liquidity markets so noisy odds aren't read as signal (floors `PM_KALSHI_MIN_VOL`/`PM_POLY_MIN_VOL`); and (3) draws a **Hold-probability trend** (Δ vs ~1w ago + a sparkline) from a new rolling `data/prediction-history.json` (read-before-wipe like `fedwatch-history.json`). Divergence is computed in `buildCalendarPayload` (`computeFomcDivergence`); the macro-release pills carry the `thin` tag too.
- **Macro / Picks — VIX term structure (`^VIX9D` / `^VIX` / `^VIX3M`).** `fetchMacroBackdrop` now reads the 9-day and 3-month VIX alongside the 30-day index and exposes a `vixTerm` block (`ratio` = spot/3-month, `state` = backwardation/contango). **Backwardation** (near-term fear richer than longer-dated = acute stress) now **confirms a risk-off regime** at a lower absolute VIX (≥16) in `detectMarketRegime` and blocks risk-on while the curve is inverted — sharpening the regime that gates entry timing, tactical puts, and gross sizing. Surfaced as a "Curve · inverted/normal" pill on the Vol-regime tile. (One-time grade/roster shift on the next bake, as with any regime input.)
- **Picks — macro event-risk entry defer (prediction-market-driven).** `computeEntryTiming` now defers entries (→ `wait`) when an **imminent, market-uncertain** macro event is near — an FOMC/CPI within `PICKS_TIMING_EVENT_DEFER_DAYS` (3) whose top prediction-market outcome is priced below `PICKS_EVENT_RISK_MAX_PROB` (70%), i.e. a coin-flip the crowd can't call. A confident event (e.g. a 98%-hold FOMC) does **not** fire, so the roster only stands down ahead of genuinely two-sided prints. Derived by `computeMacroEventRisk` from the prediction-market odds and threaded via `macroBackdrop.eventRisk`; gated by `PICKS_EVENT_RISK` (default on). Affects grades + the roster on the next bake.
- **Calendar — prediction-market odds (Kalshi + Polymarket).** The FOMC widget now shows a money-weighted **hike/hold/cut cross-check** from Kalshi (`KXFEDDECISION`) and Polymarket ("Fed decision in …") beneath the existing ZQ-futures-implied table, and macro release rows (CPI/Core CPI/PPI/payrolls/unemployment) carry a best-effort **market-implied** pill from Polymarket when a related market resolves near the release. New `fetchPredictionMarkets()` in `scripts/build.mjs` writes a `fomc.predictionMarkets` block + per-report `predictions[]` into `data/calendar.json` (also wired into `scripts/regen-calendar.mjs`). Free public reads — **no API key** — and it degrades silently (a flaky host, missing event, or shape drift just omits that slice; a one-build outage carries the prior odds forward, tagged `Cached`). Hosts/tickers/tags are env-overridable (`KALSHI_API_BASE`, `POLYMARKET_TAGS`, `PREDICTION_MARKETS=0` to disable). Live API shapes weren't exercisable from the dev sandbox (egress allowlist), so the parsing is written against the documented shapes and verified on the first real bake.
- **Top Picks — timing-gate go-vs-wait A/B in the loss diagnostic (`scripts/diagnose-pick-losses.mjs`).** The script now prints the gate's own **go vs wait** split on modeled option P&L (expectancy + win rate per arm, and the `go − wait` marginal — "does endorsing actually help?") plus the honest **gate-era sample size**, flagging "insufficient — need ≥25/arm" until forward picks resolve. This is the data-available proxy for the P0.2 2×2 (a true stop×gate grid needs the intraday path we don't store) and operationalizes the "get to significance first" prerequisite. Refactored the per-pick BS modeling into a shared `modelClosedPick` helper so the attribution table and the A/B can't drift.
- **Top Picks — "Check a position you hold" tool.** A new sub-section on the Top Picks tab: enter a contract you already own (ticker, side, expiry, strike, price paid, contracts) and get a **hold / trim / sell / wait** recommendation. It prices the contract **live** via `/api/contract` (falling back to the last build's chain when the market's closed), reads the ticker's current grade + entry-timing from `grades.json`, and applies the **same +60% / −40% premium take-profit / stop the track record resolves on** — plus grade-alignment (has the thesis flipped against your side?), the timing state, an earnings-before-expiry IV-crush warning, and a DTE/theta warning. Shows your entry, the live mark, P&L ($ and %), the grade + timing, and the plan levels. Tracked tickers only; modeled greeks; not financial advice.
- **Top Picks tab — refreshed grading overview + a "how the market tape moves the picks" explainer.** The on-tab "How the grade works" disclosure was rewritten to today's engine: the cross-sectional (relative) score, the **5th entry-timing component**, percentile tiers **floored by an absolute bar** (so the list can ship short/empty), risk-based sizing + the edge governor, and the near-the-money (0.45–0.65Δ) contract + premium-space exits. Adds a dedicated section explaining how **VIX, the 10-year yield, the dollar, and a sell-off (risk-off regime)** flow into the grade — both as direct signals and as a regime that tightens entry timing, opens reduced-size tactical puts, and trims gross. A live **"market tape" chip** (risk-off / neutral / risk-on, from the build's regime) now leads the summary so the explainer maps to today's state. Also corrects the previously **stale** copy (old ±20 tiers, 0.20–0.40Δ / ≤$35 contracts, "Positive catalyst +3", MA-stack ±1-each, "Technicals (13)", No-Trade −15..+15) that predated the P3.x/P0.x/P1.x reworks.

- **Top Picks IC bridge — grade IC + per-signal IC (research, measure-only).** `computePicksAccuracyStats` now reports `gradeIc` (Pearson corr of the signed grade vs the realized underlying move — the rigorous "does a higher grade predict a better outcome?" read, positive = predictive, negative = anti-predictive) with `gradeIcN`, plus `gradeIcOption` (conviction vs option P&L) and a per-signal `bySignal[].ic`/`icN` (each signal's stored directional contribution vs realized option P&L, n-gated at `PICKS_SIGNAL_MIN_N`). This is the drop-in that lets `W_s` be refit from realized IC (rubric §9.6); it does **not** feed weights yet. Surfaced as a "grade IC (research)" chip. On the current retired-engine closed set `gradeIc ≈ 0.03` (n=38) — the grade had **no** cross-sectional edge — a more honest read than the directional fade chip (89.5% "fade wins" there is market beta, every closed pick being a call in a falling tape, not grade skill).
- **Top Picks P1.1/P1.2 — multi-leg model + debit verticals (dark by default).** `pickContractForPick` now returns a `structure`/`legs[]`/`netDebit` shape (a single long is `structure:'long'` with one leg — purely additive, the long path is byte-identical). When `PICKS_VERTICALS=1` **and** IV rank ≥ `PICKS_VERT_IVRANK` (70), it finances the long by selling an OTM wing on the same expiry (`PICKS_VERT_SHORT_DELTA_MIN/MAX`, `PICKS_VERT_MIN_CREDIT`), cutting net vega/theta when premium is rich; `modelVerticalExit` reprices each leg honestly (long ask→bid, short bid→ask). **OFF by default** — the loss-attribution diagnostic shows losses are direction-driven, so a vertical only shrinks a wrong-side loss; the capability ships to be validated on forward data before enabling.
- **Top Picks P1.6 — real IV rank.** `attachIvRanks` reads each ticker's `data/iv-history/<SYM>.json` (ATM-30d IV vs its own history) and stamps an IV percentile/rank onto the ticker; the picks card's `ivPctile` now shows the real implied-vol percentile (was a realized-vol proxy), and `computeEntryTiming` reads it as a **side-aware soft con** (rich premium is a headwind for any long debit — a con weakens conviction for calls *and* puts, the correct sign, unlike a directional score signal). Gated on `PICKS_IVRANK_MIN_N` history.
- **Top Picks fade-the-grade research metric.** `computePicksAccuracyStats` reports `fadeExpectancyPct`/`fadeWinRate` — the directional expectancy/win rate of betting the OPPOSITE of every grade. A positive number means fading the engine would have paid (negative directional edge in-sample) — the cheapest decisive IC-sign check. Surfaced as a research chip; never feeds the engine.
- **Top Picks P0.4 — absolute quality floor under the percentile tiers ("cash is a position").** Percentile tiers alone always passed ~the same count every build, so the engine could never say "nothing worth buying today" — it force-fed a roster onto any tape. The percentile cutoffs are now floored at an absolute `|total|` bar (`PICKS_ABS_STRONG_FLOOR`/`PICKS_ABS_TRADE_FLOOR`, default the legacy ±16/±12; set the env var to 0 to disable): a name must clear BOTH the rank AND the floor, so the roster honestly shrinks (or ships 0) on a weak/risk-off tape. Verified on committed data: the roster drops from 10 force-fed names (convictions down to 7.9) to 4 (one graded call + three risk-off tactical puts). Paired with a thin-roster sizing guard (`PICKS_SIZE_FULL_ROSTER_N` = 5) that ramps gross to the full `PICKS_GROSS_TARGET` only once the roster reaches 5 names, so a 1–2 name roster holds proportionally more cash instead of concentrating the whole book into one position.
- **Top Picks P0.2 — modeled option win rate is the headline.** `computePicksAccuracyStats` now reports `optionWinRate` (fraction of repriced picks that made money ON THE OPTION) alongside the existing `optionExpectancyPct`, and every cohort slice (`byTier`/`bySector`/`byRegime`) carries an option-P&L lens (`optWinRate`/`optExpectancyPct`). The Track-record tab now LEADS with the option win rate + expectancy when gate-era picks have resolved (demoting the underlying win rate / stock-move expectancy to context), so the engine is graded on the instrument it trades, not the stock. Populates as 0.55Δ picks (which carry the entry-option snapshot) resolve.
- **Loss-attribution diagnostic (`scripts/diagnose-pick-losses.mjs`).** Read-only, no-network tool that models each resolved pick's option P&L (Black-Scholes, entry IV implied from the stored mid, IV held to exit) and classifies every loss as direction-driven vs theta/vol-driven — the analysis that decides whether structure work (verticals/premium stops) or signal/stand-down work is the higher-leverage fix. On the current 38-pick record it finds 100% of losses are direction-driven (modeled option expectancy −39.1% vs the −7.6% stock-move headline, ~20% round-trip spreads on top).

### Changed
- **Top Picks — trailing premium take-profit (let winners run; `PICKS_OPT_TRAIL`, default ON).** `resolvePickOutcome` no longer caps every win at a flat +60%. Once the **peak** modeled option gain arms at `PICKS_OPT_TP_PCT` (+60%), the exit floor ratchets to `max(peak·(1−PICKS_OPT_TRAIL_GIVEBACK 0.33), +60%)` — it locks **at least** the old flat TP and trails a runner upward, exiting only on a 33%-of-peak give-back. Long-premium P&L is right-tail-driven, so capping at +60% truncated exactly the trades that pay for the book; this is strictly Pareto over the flat TP (never locks less). Recorded outcome is by the **sign** of the modeled P&L at the trigger, so a violent gap back through the floor between build samples is booked as an honest give-back, not a phantom win. Peak tracked per-pick as `optMfePct`. `PICKS_OPT_TRAIL=0` reverts to the flat TP. Needs the entry-option snapshot (gate-era picks).
- **Top Picks — tighter spread gate + harder spread weighting (`PICKS_CLEAN_MAX_SPREAD_PCT` 0.12→0.10).** Bid/ask is a first-order tax on a single-leg long (the loss diagnostic measured ~25% round-trip on the legacy OTM picks). The roster spread cap is tightened to 10% (now env-overridable) and the contract composite weights spread far harder (0.13→0.24), saturating its penalty at `PICKS_SPREAD_PEN_REF` (10%) so the tightest-spread survivor wins. Verified the current roster is unaffected (LLY/SLV/EWY/NKE contracts all sit at 3.9–8.7%).
- **Top Picks — IV rank is now a GATE, not just a nudge (`PICKS_IVRANK_VETO`, default ON).** `computeEntryTiming` upgrades the rich-premium read from a soft con to a **strong con** once a name's own-history IV percentile clears `PICKS_IVRANK_VETO` (90) — which blocks a `go` (demotes to `wait`, not enrolled) and shaves the timing contribution. The engine no longer endorses a **naked long bought at the 90th+ percentile of a name's own vol**, including a risk-off "tactical put" bought into a VIX/IV spike (long vol after the move — the exact failure the review flagged). Side-aware (weakens conviction for whichever side, never flips it); set `PICKS_IVRANK_VETO=0` to disable. Bounded behavior change — it can only *reduce* endorsement/conviction at vol extremes, never mint a pick.
- **Top Picks — debit verticals auto-engage in rich-IV / negative-edge conditions (`PICKS_VERT_AUTO`, DARK).** New auto policy: when on, `pickContractForPick` finances a rich-IV long (IV rank ≥ `PICKS_VERT_IVRANK` 70, or ≥ `PICKS_VERT_NEGEDGE_IVRANK` 50 on a measured-negative-edge book) as a **debit vertical** instead of buying naked premium — without flipping the master `PICKS_VERTICALS`. Sizing + the modeled-exit repricer are now fully vertical-aware (premium = `netDebit`, **net delta** across both legs, `modelVerticalExit`). **Dark by default** (`PICKS_VERT_AUTO=1` enables): shipping it live needs the pick card to render two legs (it shows the net debit + breakeven today, not the spread structure / capped max-profit), and the loss attribution still shows losses are direction-driven. Negative-edge measured via the shared `realizedOptionEdge` helper (refactored out of `computeEdgeScale`).
- **Track record tab — split into sub-tabs to cut the scroll.** The Track record page was one long stack (a wall-of-text explainer, ~12 stat chips + 4 cohort bar charts, the Top-10 roster expanded, two 40-row logs, then every open/resolved pick). It now opens with a compact **Scorecard** and an in-tab segmented nav (reusing the Grade tab's `.opt-tabs` pattern): **Scorecard** (headline win rate / expectancy / wins-losses-open + win-rate-by-tier; the research chips — fade-the-grade, grade IC — and the sector/regime/A-B cohort bars demoted into a collapsed "Advanced & research stats" disclosure), **Top 10** (picks in & out), **Activity** (grade-change + crossings logs), and **Picks** (open & resolved). One short view at a time; tab labels carry live count badges; the long explainer moved into a "How this works" disclosure. Last sub-tab persists in `localStorage`. Nothing was removed — every section is still reachable.
- **Fixed: `?tab=track` deep-links resolve.** `track` was missing from the page-tab allowlist, so a shared `?tab=track` URL silently fell back to Home (clicking the tab worked, but the link didn't). Added it so the deep-link lands on the Track record tab.
- **Top Picks — collinearity-collapse decorrelation (dark by default).** `computeCrossSectionalScores` can now collapse correlated converted-signal clusters (`SIGNAL_CLUSTER`: growth / value / momentum / mean-rev / flow) by scaling each signal's contribution `1/√K` (K = its cluster's firing signals for that name), so a cluster of correlated signals contributes like ~one factor instead of K× — capping the loading on whatever common beta (usually the Tech/AI complex) the universe shares (the audit's root-cause #1: z-scoring fixes each marginal but never touches the covariance). `PICKS_DECORRELATE` default **OFF**: it changes the grade scale (roster 4→1 on the committed sample), and an unvalidated score change won't ship live on a losing engine — the scaling is itself a forward-validation target.
- **Top Picks P0.3 — premium-space exits.** `resolvePickOutcome` now resolves on the MODELED option P&L *before* the underlying-level TP/cut: take profit at `PICKS_OPT_TP_PCT` (+60%) and cut at `PICKS_OPT_STOP_PCT` (−40%) of entry premium. A symmetric underlying stop maps to a wildly asymmetric option move, so the premium stop truncates the −60% tail the structural cut lets run. Levels are flat (vol/DTE-blind) for now — the AXIS (premium, not stock) is the first-principles fix; the levels get regime-aware once a forward sample exists. The structural underlying cut stays as the broken-level exit (with a note that it can't be honored intraday on a gap — the premium stop is the real bound).
- **Top Picks P1.3 — edge governor.** `applyPickSizing` scales the deployed gross by the trailing realized OPTION expectancy (`computeEdgeScale` over the prior `closed` set, threaded from `picksAccuracyPrev`): full gross at a ≥0% edge, ramping to a floor (`PICKS_EDGE_SCALE_MIN`) at a deeply negative one (`PICKS_EDGE_FULL_CUT_EXP`), a conservative default below `PICKS_EDGE_MIN_N` results. A measured-negative-edge book no longer redeploys 80% gross every build. `rosterMeta.edgeScale` records the multiplier.
- **Top Picks P1.4 — liquidity as a hard candidacy gate.** `buildTopPicks` computes the tradeable (`requireClean`) contract up front and DROPS names with none BEFORE ranking, so the roster ranks the universe of *tradeable* names (not merely graded ones) and the candidate slice can't be filled by high-grade names we can't trade out of. `rosterMeta.untradeable` counts the drops; the contract is reused in the loop (no double compute).
- **Top Picks P1.5 — premium-at-risk sizing.** The option-risk denominator in `applyPickSizing` now adds the theta bled over a typical hold (`PICKS_SIZE_HOLD_DAYS`) + a modeled IV mean-reversion drop (`vega × min(IV−HV, PICKS_SIZE_IV_DROP_CAP)`) on top of the delta-to-stop loss, so short-DTE / rich-IV contracts size smaller than a calm one with the same delta. `vega` is now returned on the contract.
- **Top Picks P2 — term-structure gate + earnings-eve exit.** `computeEntryTiming` adds a soft con when the IV term structure is in backwardation (front-month richer than the back by ≥ `PICKS_TIMING_BACKWARDATION`) — buying the most expensive point on the curve. `resolvePickOutcome` adds a forward earnings-eve exit: if a print creeps within `PICKS_EARNINGS_EXIT_DAYS` of the mark, close at the pre-crush modeled mark rather than ride the IV crush.
- **Top Picks P0.1 — honest fills in the modeled option P&L (enter at ask, exit at bid).** `modelOptionExit` now enters at the contract's ASK and haircuts the BS exit toward the BID using the stamped `spreadPct`, instead of a free mid-to-mid round trip — charging the 12–18% bid/ask the contract selector admits. `pickContractForPick` now returns `spreadPct`, and the accuracy enroll snapshot stamps `bid`/`ask`/`spreadPct` so the repricer (and the live theta-stop's unrealized-loss read) can use them. Legacy entries without the quote fall back to mid (graceful). This stops `optionExpectancyPct` from flattering every result the moment it populates.
