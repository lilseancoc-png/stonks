## [Unreleased]

### Added
- **Price chart on the Technicals tab — Robinhood-style intraday, with range tabs.** Each ticker draws a price chart at the top of the Technicals pane with **1W / 1M / 3M / 1Y** tabs (default **1M**). **1W and 1M render 30-minute INTRADAY bars** (regular session only — a clean Robinhood-style line) so short-horizon shapes like an intraday head-and-shoulders are actually visible; daily closes smooth them into a single spike. **3M and 1Y stay daily** with range-adaptive SMAs (20/50-day on 3M, 50/200-day on 1Y) + a high/low band + volume, computed over the full series so a zoomed window still gets a correct SMA. The bake now fetches intraday (one extra Yahoo call/ticker) and persists two compact series — `priceSeries` (~1yr daily) and `intradaySeries` (~1mo of 30m closes) — that the browser reslices per range; switching is CSS-only (hidden radios). Falls back to daily slices for 1W/1M when a ticker has no intraday series (older payload / failed fetch).
- **Dated-catalysts section in the Top Picks / Grade Narrative breakdown.** The Narrative pillar's expander now lists each ticker's AI-extracted forward catalysts (contract decisions, launches, court rulings, investor days, …) as dated, category-tagged chips reusing the Calendar tab's styling — answering "what *is* the catalyst" instead of only showing "news sentiment bullish". The data (`data.catalysts`, up to 3 per ticker) was already baked and surfaced only in the Calendar tab; this carries it into `picks.json`/`grades.json` and renders it via the shared `pickPillarPanel`, so it lights up the Top Picks card, the grade-any-ticker search card, and the Track-record roster at once. **Presentational only** — the ±3/0 Positive/Negative-Catalyst score stays news-sentiment-driven (no scoring change). Renders nothing when a ticker has no catalysts (byte-identical markup), so legacy/empty payloads are unaffected (#320).

### Changed
- **Narratives call moves its system prompt to `config.systemInstruction`** (`generateMarketNarratives`) instead of inlining it into `contents`, matching the ticker-judgment / signals / chart calls so the prompt forms the implicit-cache key prefix. Cost-neutral in practice (the 8 daily builds sit past the cache TTL; only the in-build retry loop can hit it) — a consistency/correctness change, with no change to the generated narratives.

### Perf
- **Per-ticker Major-Contract + Guidance signals can fold into the combined judgment call** (new `AI_SIGNALS_COMBINED`, **OFF by default**). When on (and `AI_COMBINED` is on), `generateTickerJudgment` also returns the `signals` field that previously required a dedicated per-ticker `attachAiContractGuidance` round-trip — removing ~one flash-lite call per ticker per build (~138 calls × 8 builds/day). The extraction/validation mirrors the dedicated pass exactly, so `data.aiSignals.{guidance,majorContract}` (a `scoreFundamentals` input) is byte-identical in shape; the appended SIGNALS prompt section + schema field are constant across tickers so the implicit-cache prefix still matches. Kept off until an A/B parity check confirms the merged model reads track the dedicated reads (`scripts/ab-signals-merge.mjs` diffs two `grades.json` builds); enable in prod via the `AI_SIGNALS_COMBINED=1` Actions Variable. The split path (`AI_COMBINED=0`) and the default still use the dedicated pass — byte-identical to before.
- **Empty `n/a` fundamentals lines are pruned from the AI prompt** (`formatFundamentalsForPrompt`). Sparsely-covered names (ETFs/ADRs/micro-caps) no longer send dead `Field: n/a` rows or now-empty section headers to the combined ticker-judgment call — fewer input tokens, same information conveyed. Fully-populated tickers produce a byte-identical snapshot (only absent metrics are dropped), so the common case is unchanged.
- **Article-body fetch timeout cut 8s→4s** (`ARTICLE_FETCH_TIMEOUT_MS`). The per-ticker news pipeline fetches up to 5 article bodies before each AI call, and on GitHub-Actions egress IPs most of those fetches are blocked/stalled and burned the full 8s before timing out (~16s/ticker across the two fetch waves) — the single biggest drag on the build's AI stage. A body that loads at all almost always returns in <3s, so 4s keeps the fast hits while halving the dead wait on the (majority) failures. A missed body degrades gracefully — the AI grounds the take on the headline title + publisher + date. Pure HTTP timeout: no Gemini/quota impact, no change to request rate (no new rate-limit exposure) (#319).
- **AI "miss-sweep" retry wait trimmed 30s→15s** (new `AI_MISS_SWEEP_WAIT_MS`, applied to the ticker-judgments, fundamentals, and chart-pattern passes). After each AI pass, tickers that missed get one retry after a pause to let a transient blip clear. The flat 30s was sized to "sleep through a 60s quota window," but quota 429s are now rare (the build peaks ≈355 RPM vs the 600 pacer), so misses are almost always transient network that recovers in seconds; 15s keeps the recovery benefit at half the dead wait, and a real quota stall would outlast either value (the ticker then degrades to no-AI-take). Token-neutral (#319).
- **Unusual-flow AI explanation pass widened 5→15 concurrent calls.** `AI_FLOW_CONCURRENCY` is the *only* genuine AI-concurrency cap in the codebase (the build's per-ticker passes are already unbounded `Promise.all`). The scan's flow-explanation calls are gated solely by this cap — there is **no `AI_RPM` pacer** on the scan path — and Flash-Lite peaks at just ~355/4K RPM, so the quota has large unused headroom. 15 fans the typical ≤20-anomaly batch out in 1–2 waves instead of ~4, shaving ~10s off a heavy opening scan. Token-neutral (re-flags still hit the per-contract cache). Small, once-per-day win; the scan's wall clock is dominated by the Yahoo chain fetch, not AI (#319).
- **Unusual-flow scan worker pool restored to the build-matched 6-wide concurrency.** `scan-unusual.mjs` `SCAN_CONCURRENCY` was 4 while its own comment claimed it tracks `build.mjs` `TICKER_CONCURRENCY` — which had since been bumped to 6. Raising it back to 6 cuts the hourly scan's wall clock ~1.5× (~25s → ~16s). Each scan ticker fetches only `FRONT_EXPIRATIONS=2` chains at the unchanged `POLITENESS_MS` pacing, so the aggregate Yahoo `options()` rate at 6 workers is ~17 req/s — *below* the build's empirically-clean ~18 req/s on the identical endpoint/runner IP — and the two workflows never run concurrently (shared concurrency group). No AI calls added, so Gemini spend is unchanged (#319).
- **Daily build's independent calendar fetches now run concurrently.** `main()` fetched macro releases (FRED/BLS), the Fed Funds rate (NY Fed EFFR), the FOMC schedule (Fed.gov), and Nasdaq earnings sessions strictly in series even though they hit different hosts with no cross-dependency. They now run in one `Promise.all`, overlapping the round trips and saving ~8–10s off the bake. One request per host means no single host's rate goes up. To stay a **zero-semantic-delta** change, macro→Fed-rate run sequentially *within* one lane (both share the module-level `_fredFirstAttemptFailures` FRED-cascade counter, which is deliberately scoped to carry across the two), while the two FRED-free fetches overlap them; the fifth source (FedWatch/CME ZQ) still runs after the batch since it depends on the Fed rate + merged FOMC schedule. Data is exactly as fresh as before — every source is still fetched live each build; the speedup is pure I/O overlap, not data reuse. Token-neutral — no AI calls touched (#319).

### Docs
- Daily-build schedule: the full bake now runs **8× per trading day** — 9:30 ET (market open), then hourly 10:00–16:00 ET (the close) — replacing the previously-documented 9:00/12:00/17:00 (~3×/day). Timing lives in cron-job.org, split across two jobs (`30 9 * * 1-5` for the :30 open + `0 10-16 * * 1-5` for the top-of-hour cadence, both America/New_York) since one cron line can't mix the two minute values. Synced `daily.yml` header, `README.md` ("How it updates"), and CLAUDE.md (bake-time, AI-cache, and workflow-scheduling sections).

### Changed
- **Chart-pattern detector now rates the 1-MONTH INTRADAY chart (was daily) + scales reliably.** The pattern that feeds the Top Picks grade is now read off ~1 month of 30-minute intraday bars instead of daily closes — short-horizon reversals (an intraday head-and-shoulders, etc.) live there and vanish into a single spike on daily bars, so the detector was structurally blind to them. It re-rates **~2×/day** (open + midday, an ET AM/PM cache bucket) since intraday bars change every 30 min, and on the next bake re-reads every name once (`img4` cache version). Also fixes a real reliability bug: the multimodal pass fired ~137 chart images in one burst, rate-limiting Gemini so **~half the universe (66/137, including MSFT) ended a build with no pattern verdict at all** — it now runs at a bounded concurrency (`AI_CHART_CONCURRENCY`, default 6) and **falls back to a text-only read** when an image call fails, so a burst can't leave a ticker undetected. The detector image is the clean regular-session intraday line with ≈1-day/≈3-day smoothing overlays.
- **Chart-pattern detector now predicts a head-and-shoulders (and the other 6) *while it's forming*, not just after it completes.** The detector reports a `stage` — **forming** (the shape is partially built, e.g. left shoulder + a higher head and price rolling into a right shoulder, but the neckline hasn't broken) or **confirmed** (the decisive break has happened) — plus the `neckline` level and one-line `confirm` / `invalidate` / `target` reads. The Technicals card surfaces a "⚠ Forming" badge with those levels so you can act before confirmation. Scoring stays conservative: a **confirmed** pattern scores flat ±1 by direction as before, a **forming** one scores **0** (early warning, surfaced but doesn't move a pick until price actually breaks). The detector image is also zoomed to a ~75-session window (was ~140) with 20/50-day SMAs so a building reversal is large and legible, and the per-ticker cache key is bumped (`img3`) so every prior verdict re-reads once.
- **Chart-pattern detector now *sees* the chart instead of reading numbers.** `generateChartPattern` rendered the daily series as a plain text table and asked the model to infer geometry from a column of numbers — a visual task done blind, which is why clear formations (e.g. NOW's head-and-shoulders) came back "None". It now renders the same window to a PNG (new dependency-free `lib/chart-image.mjs`, pure JS + Node `zlib`) and sends it as a multimodal image alongside the numeric series (kept for exact level/date citations), upgrades the model from Flash-Lite to **Flash** (`AI_CHART_MODEL`, since Lite reads images poorly) with a small thinking budget, and version-bumps the per-ticker cache key (`img2`) so every cached pre-image verdict is re-read once. Only the moving-average overlays the window can actually compute are named to the model (a 140-bar series has a 50-day line but no 200-day one). Image render is best-effort — a failure falls back to the old text-only path, so the bake never breaks on it. Cost stays low: the chart-pattern cache means this fires ~once/ticker/trading day.
- **Top Picks now only ever recommends a contract the grader itself would pass.** Previously `pickContractForPick` shipped the best contract it found even when its own grade fns called it `bad` (2 of 10 live picks — ASML, CLS — were `overall:"bad"`), and its hard gates were *looser* than the Grade tab's "bad" lines (spread admitted to 18% but the grader flags >15%; OI floor 50 but liquidity is "thin/bad" <100; no theta gate at all), so clicking a pick's "Grade this contract →" frequently tripped a hard-fail and surfaced the "Try this instead / Switch to this contract" swap. The roster path now runs with `requireClean` (`buildTopPicks` only): buffered self-consistency gates — spread ≤12%, OI ≥100, DTE ≥21, theta ≤2.5%/day — that sit *inside* every grade-bad line, plus an explicit refusal of any candidate the grade fns would call bad (and a return-null invariant). A name with no clean contract is dropped and the next conviction-ranked candidate backfills. The delta band stays 0.20–0.40 (an OTM pick that can still appreciate; `|Δ|` 0.20–0.40 is never a grader hard-fail) and is no longer folded into the contract's `overall` rollup (it always graded "fair" and was capping every pick at "fair"). The universe-wide `autoPick`/"★ Top-Picks grade" banner keeps the looser documented gates, so the on-screen spec text is unchanged (#317).
- **A vetted Top Pick is never offered a swap.** When the user clicks through from a pick card, the Grade tab now trusts the bake's `requireClean` verdict instead of re-deriving it from live quotes: it suppresses the mechanical hard-fails / "Try this instead" alternative for that exact contract, shows a "Top Pick · contract vetted" verdict, and frames any live deterioration as transient quote drift (re-checked each build) rather than condemning the pick. Disengages the moment the user changes strike/expiry/type, and never applies to the `autoPick` banner (whose contracts can legitimately be bad) (#317).

### Fixed
- **Chart-pattern detection failed for ~70% of tickers (incl. every Top Pick) — truncated JSON, not rate-limiting.** The first intraday-detector build left 98/138 names with no pattern verdict. Build logs showed the cause: on `gemini-2.5-flash` the **thinking tokens count against `maxOutputTokens`**, so a 512 thinking budget against a 600 ceiling left ~80 tokens for the reply — and the now-larger forming-stage JSON (`stage`/`neckline`/`confirm`/`invalidate`/`target`/…) was cut off mid-string, failing `JSON.parse` (208 "Unterminated string" errors vs only 4 rate-limits). Raised `maxOutputTokens` 600→**2048** so thinking + the full JSON both fit (it's a ceiling, not a cost). Also re-rated correctly now that the cache stores results.
- **Cheaper chart-pattern calls (same functionality).** Two waste cuts on the per-ticker detector: the numeric text series handed to the model is **downsampled ~286→~37 rows** (the full-resolution IMAGE still carries the shape + levels; the text only anchors approximate levels), trimming ~2.2k input tokens/call (~85%); and the thinking budget is trimmed 512→**384** (`AI_CHART_THINK` to tune), since thinking is billed at the pricey output rate. No change to detection inputs the model actually needs — the image is unchanged and all output fields remain. Forcing `catalysts` to be a required field (#321) stopped the empty arrays but caused `flash-lite` to stuff them with content the prompt explicitly forbids — the next-earnings print and far-dated events (in the first post-fix build, 115/120 grade catalysts were earnings-titled and 105/120 fell outside the 30-day window). The parse loop now enforces those two rules **deterministically** instead of trusting the prompt: it drops any catalyst whose title mentions earnings (or whose date equals the known next-earnings date) and any date outside the forward `CALENDAR_DAYS_AHEAD` (30-day) window. Verified against the last build's data — 120 → 4 catalysts, keeping only the legitimate in-window events (AAPL WWDC, GOOGL offering, NVO ADA, BE tariff). The Top Picks / Grade "Dated catalysts" section now shows real catalysts or nothing — never earnings leaks (#322).
- **Ticker catalysts are now actually extracted (were empty on every build).** The per-ticker AI judgment returned `catalysts: []` for all 138 names across every build to date — even when a clearly-dated qualifying event was in the input (e.g. AAPL's WWDC June 8, present in both the source headlines and the model's own paragraph). Root cause: `catalysts` was an *optional* field in `TICKER_JUDGMENT_SCHEMA` and `gemini-2.5-flash-lite` (`thinkingBudget: 0`) reliably skipped populating it, abetted by a heavily skip-biased prompt. Fix is token-neutral: (1) move `catalysts` into the schema's `required` list so the model must produce the array (an empty array still satisfies it when no event truly exists — this forces consideration, not invention); (2) add an "actively populate when a dated event is present in the input" directive to the CATALYSTS prompt section to counterbalance the existing skip guardrails, leaving the never-fabricate-a-date rules intact. This makes the #320 Top Picks / Grade "Dated catalysts" section actually surface content. Validates on the next market-hours build (AAPL → WWDC is the regression check) (#321).
- **Pre-market quote no longer fails a pick on spread.** Before 09:30 ET Yahoo returns one-sided/zeroed quotes, ballooning the bid/ask spread past the 15% "wide" line for an otherwise-fine contract; the Grade tab had no guard and emitted a wide-spread deal-breaker. It now suppresses the spread hard-fail when a side is missing (`bid`/`ask` ≤ 0) or the session isn't regular — a stale-quote artifact, not a bad contract (#317).
- **Pick card and Grade tab now agree on the liquidity chip.** Build-side `gradeLiquidity` graded "good" at OI ≥500 while the browser used ≥100, so an OI 100–499 pick read "Light" on the card but "Liquid" in the grader; the build copy now matches the client (good ≥100 / fair ≥10 / bad <10) (#317).
- **IV-history no longer resets for flaked tickers.** `collectIvHistory` (the only carry-forward of `data/iv-history/<SYM>.json` across the build's `rm -rf data/` wipe) keyed its output off *today's* successful chains and gated the prior-file load behind a fresh ATM-IV computation, so any ticker that flaked from Yahoo (the build tolerates up to 25% missing) or had no computable ATM IV that build had its entire accumulated IV series permanently wiped. It now seeds from every existing iv-history file on disk first, then layers today's sample on top — no series is lost on a partial/IV-less build.
- **13F filings with namespace-prefixed XML now parse.** The namespace-strip regex dropped the slash from closing tags (`</ns1:infoTable>` → `<infoTable>`), so the infoTable block matcher found nothing and every prefixed filing parsed to **zero** holdings, silently degrading that firm to the curated baseline with no real QoQ deltas. The strip now preserves the `<`/`</` boundary.
- **Segment-revenue donut over-count.** `dropGenericRollups` detected a company-wide catch-all rollup with a fixed `>0.95×`-of-total ratio tuned on an annual figure, so a quarterly `Product` rollup at ~0.93× of total slipped through and inflated the breakdown (LLY: a $58.6B donut for a $19.8B quarter). It now detects a rollup by redundancy — a *large* generic member (≥50% of total) whose siblings already reconcile to the whole company (≥90%) — which is scale-independent and keeps legitimate single lines (small or dominant). `SEGMENT_PARSER_VERSION` bumped to 15 so cached accessions re-parse.
- **Phantom "recently ended" trends.** Autogenerated `<Industry> Watchlist` coverage-filler narratives were persisted into `trends-history.json` without their discriminator flag, so when a real narrative began covering a Watchlist's orphan tickers the Watchlist's disappearance surfaced as a trend that "ended". The snapshot now carries `autogenerated` and `computeRecentlyEnded` skips filler.
- **OI tracker ingested expired chains at EOD.** `scan-oi.mjs` took the front two expirations with no recency filter, so the post-close EOD scan spent a slot on the just-settled 0DTE chain for daily-expiry names (SPY/QQQ/IWM), letting frozen settlement OI/volume drive the walls / cpRatio / gamma score. Expired expirations are now filtered out (live until 21:00 UTC of their day) and the first-slot ingest re-fetches the first live expiration instead of trusting Yahoo's `options[0]`.
- **CPI / Core-CPI YoY** now read the non-seasonally-adjusted index (`CUUR…` / `CPIAUCNS` / `CPILFENS`) the published year-over-year headline is computed from, instead of the seasonally-adjusted series (which left a residual seasonal error vs the number markets quote). MoM still uses the SA series.
- **`volume-flags.json` `srBreakCount`** counted every S/R crossing per bucket-hit — including the `conviction: "None"` "No confirmation" placeholders the engine doesn't treat as flags — so the eyebrow stat was roughly double the genuine confirmed breaks. It now counts confirmed breaks once per ticker, matching `hourlyFlagCount`.
- **VIX percentile rank** ranked today's VIX against a distribution that already included today's just-upserted entry (so it could never read 0 and was biased up by ~1/n); it now excludes today's own ET-dated sample and ranks against the trailing distribution.
- **Evening-ET earnings dates** derived from the UTC instant mis-dated after-close (AMC) prints that cross 00:00 UTC by +1 day, desyncing from the ET-keyed calendar / Nasdaq session join / `earningsInsideWindow`. Timestamps with a real intraday time now use the ET wall-clock date; time-less (00:00 UTC) dates keep the UTC calendar day as before.
- **Grade-tab live pill** paired a fresh polled spot with a stale day-change carried over from the last quote; it now re-derives change/%-change off the cached previous close against the new spot so the two reconcile.

### Changed
- Top Picks grader: tuned three rubric criteria to the source spec. **Fundamentals · Earnings Surprise** now needs a ≥10% beat/miss to score ±1 (was ≥1%) — 25%+ still scores ±2, anything inside ±10% reads in-line at 0, so small surprises no longer move the score. **Mechanical · Put/Call Ratio Extreme** trips its contrarian-bullish +2 at a P/C ratio >1.15 (was >1.25), widening the "extreme fear" band (the bearish <0.65 greed side is unchanged). **Peer comparison** is now scoped by **sub-industry** (the curated `INDUSTRY_OF_TICKER` map) rather than broad sector — a pick is stacked against true competitors (CRWD vs PANW/FTNT/ZS within Software Infrastructure) instead of the whole Technology sector, in both the "vs peers" list and the deterministic analysis paragraph.
- Top Picks grader: realigned four signal weights to the source scoring spec. **Mechanical · Put/Call Ratio Extreme** now scores ±2 (was ±1) — an extreme P/C reading is a heavier contrarian signal. **Narrative · Media** now scores a bearish coverage surge -2 (was -1; bullish stays +1) — negative media weighs twice as heavy as positive. **Technicals · 100D SMA** now scores ±1 (was ±2) — flat with the 20D/50D rungs per spec (the 100D *S/R* rung stays ±2, unchanged). **Technicals · Chart Pattern** now scores a flat ±1 regardless of model confidence (was ±2 on high-confidence reads) — drops the high-confidence doubling. Net effect: P/C-extreme and bearish-media names shift more, high-100D-SMA and high-confidence-pattern names shift less; some Top Picks grades move.
- Top Picks tenure/streak chips now count **trading days** a name has held its spot, not builds survived. Both the detail card's ⏱ badge and the landing-card chip derive the count from each pick's `firstSeen` as U.S. market sessions between then and now (weekends + full-day holidays excluded via the existing `MARKET_HOLIDAYS` calendar, so the streak doesn't inflate over a weekend; half-days still count), replacing the old per-build tally (`buildCount`, now dropped). Shown once a name carries over into a 2nd session. `firstSeen` stamping is now a shared `applyPickFirstSeen` helper so `regen-picks.mjs` preserves the streak across a render-only regen (previously it dropped `firstSeen`, hiding the chips until the next full build).
- Market narratives: a sector's grade (stance + strength) is now **computed**, not AI-guessed — a two-level rollup where each industry group's grade is the signed-strength average of its narratives (bullish +strength / bearish −strength) and the sector grade is the average of its industry-group grades. The AI keeps the qualitative `thesis`/`watchFor`; the math owns the number (`computeSectorGrades`). The sector overview now exposes the per-industry-group breakdown so the rollup is visible.
- Top Picks grader: the Narrative pillar's `sectorNarrative` ±2 signal now **fades by lifecycle + hype** — Peak halves the conviction, Challenges neutralizes it, Collapse flips a former tailwind to a fade, and a fundamentals-vs-hype score ≥70 halves the signal. Late-stage / hyped stories are treated as exhaustion risk rather than fresh tailwinds, so some Top Picks grades shift.
- Top Picks grader: split the single RSI 14 technical signal into **two** signals (technicals goes 12 → 13). **RSI Movement** (±1) is the 50-centerline momentum read — RSI above 50 and rising over the prior 5 sessions +1, below 50 and falling -1, otherwise 0. **RSI Reading** (±3, the heaviest single technical signal) is the contrarian extreme read — 75+ overbought -3, 25 or below oversold +3, otherwise 0. Replaces the old composite (oversold <35 +1 / overbought >70 -1 / mid-range ±5pt momentum). Reads the already-computed `rsi`/`rsi5d` fields; the browser's separate per-contract YES/NO "aligned score" RSI conviction is unchanged.
- Macro calendar + Fed Funds rate now fetch from their **source-of-record** first — BLS Public Data API for the CPI/PPI/payrolls/unemployment/JOLTS series and the NY Fed EFFR endpoint for the effective rate — with FRED demoted to a fallback behind both. Takes FRED's frequently-throttled Cloudflare path off every build's hot path (no more ~25–50s of 429/timeout "cascade") while keeping it as a backstop. Adds an optional `BLS_API_KEY` for registered BLS access (500 queries/day, 20yr history; unset still works unauthenticated). `api/fed-rate.js` likewise tries NY Fed EFFR first, FRED CSV as fallback.

### Added
- **Top 10 — picks in & out roster** — the Track record tab's "Picks in & out" section is rebuilt around a new `data/picks-roster.json` snapshot: the current 10-name Top Picks list, each row badged IN (new this refresh) / HELD / NEW-coverage, with the prior→current **per-pillar deltas** (all four pillars, not just the top two), the names that **dropped out** of the Top 10 (paired to the entrant that took their slot, flagged "out-ranked" vs "below the ±16 bar"), and a per-pick **upgrade/downgrade forecast**. The roster diff runs on the prior visible top-N plus the pre-wipe whole-universe grade snapshot (`gradesHistoryPrev.latest`), so it's immune to the pre-market pick collapse and catches a name that leaves the Top 10 by being out-ranked while still above the bar (which the ±16 crossing log can't). The forecast is deterministic — it reads each pick's pre-computed pillar signal scores (RSI extreme, 52-week proximity, RSI momentum, guidance, analyst-target headroom, narrative lifecycle stage, IV percentile), normalizes every read to the trade's direction, and flags an earnings-before-expiry binary catalyst — with an optional **AI one-liner** gloss (`AI_PICKS_FORECAST_MODEL`, hybrid — self-skips without `GEMINI_API_KEY`, capped at 10/build, on the shared AI budget). Clicking any row reveals the full 4-pillar grading rubric (reusing the Grade tab's `pickPillarPanel`) with the pillar deltas and forecast factors. The old chronological ±16-bar log is kept below as a collapsed "Recent crossings". `regen-picks.mjs` writes the roster too (deterministic, AI-free).
- Market narratives now carry a **lifecycle outlook** alongside the existing 6-stage stepper: each narrative gets a `lifecycleOutlook` `{rationale, nextStage, trigger}` from the AI — *why* the story sits at its current stage right now (the evidence), *what stage* it most likely enters next, and the *specific signal + rough timing* that would confirm that transition. Rendered as a "Why here / Next / Watch for" block under the stepper on every narrative card; the Next chip is tinted red when the story is advancing toward collapse and green when recovering up the arc. The sector-overview banner reuses its dominant active narrative's outlook (the same narrative that already sets the sector's computed lifecycle stage). New `nextLifecycleStage` helper defaults `nextStage` to the next stage along the arc when the model omits it; older cached narratives without the field render nothing (graceful degrade). `NARRATIVES_MODEL` prompt + schema extended; 32768-token cap unchanged (thinking budget is zeroed, ample headroom).
- **Picks in & out tracker** — a new `data/picks-changes.json` rolling log records *why* a name crossed the ±16 conviction bar onto (entered) or off (exited) the actionable Top Picks set each build, surfaced as a "Picks in & out" section on the Top Picks → Track record tab. Detection runs on the grade index (the same pre-wipe `gradesHistoryPrev.latest` snapshot the grade-change log uses), so it's immune to the pre-market quote collapse that transiently empties the visible picks list. Each event carries a deterministic pillar-delta reason (e.g. "Cleared the ±16 conviction bar — Technicals +4, Narrative +2") plus an optional **AI one-liner** that folds in the per-ticker news take (`AI_PICKS_CHANGE_MODEL`, hybrid — self-skips without `GEMINI_API_KEY`, capped at 12 events/build, routed through the shared AI budget). A **hysteresis dead-band** (enter at ≥16, exit only below 14, with per-symbol in/out state read from the rolling log) stops a score parked at the bar from spamming entered/exited every build — the analogue of the grade-change log's min-delta guard. `regen-picks.mjs` writes the deterministic events too (no AI). Pre-read before the `data/` wipe like the other accumulating logs; pruned to 30 days / 200 events.
- Market narratives now carry a **6-stage lifecycle** (`lifecycleStage`: catalysts → amplification → validation → peak → challenges → collapse) on every sector and sub-industry narrative, kept alongside the existing active/building/fading `status`. The Narratives tab renders it as a stepper (rising stages read accent, the post-peak downslope reads red). The narratives AI prompt gained a lifecycle primer; the 3-state status default backfills the stage on older cached data.
- Market narratives now answer the **six-question framework**: each sector and narrative carries a **bull / base / bear case** and a 0–100 **fundamentals-vs-hype** gauge (`hype: {score, label, rationale}`), surfaced on the cards as a scenario block + a fundamentals→hype meter. ("Dominant narrative" reuses the existing thesis; "what would shift it" reuses the existing watchFor.) `NARRATIVES_MODEL` output cap raised 16384 → 32768 for the richer schema.
- Top Picks landing cards now show a `⏱ Nd` day-streak chip (how many trading days in a row the ticker has held a top-picks spot), mirroring the detail card's existing tenure badge. Shown only when the streak is >1 day.
